# 笔记模型（Note Model）

> L3 领域概念规格。回答"笔记到底是什么"，并定死节点 / 基板 / 关系 / 组装四要素。
> 承接内核 [`storage-design.md`](./storage-design.md)、[`domains.md`](./domains.md)、[`kernel.md`](./kernel.md)；
> 对象模型 / 基板 / 内存态与存储态见 [`data-model.md`](./data-model.md)。
> 注：**基础数据格式是"基板"（正文行序列），`note` 只是它的一个角色**（`data-model.md` §5.1）。

状态：**草案 v0.3**（行序列 + 行内区间样式、关系落 DB、通用版本引擎**已实现**；画板/手绘编辑未实现）

> **2026-09-19 现状导引**：目录为 `feature/note/`；note 已拆 **`NoteData(Block)` + `Note(Domain)`**（数据 + 域服务）。
> 旧 QML 编辑器（`EditorArea.qml` / `Backend.currentBlocks`）**已随 UI 删除**，编辑器待重建（`src/app`）。以代码为准。

## 1. 一句话定义

> **笔记是思考的最小可移动单元，写给未来的自己与相邻的念头。**
> 内容在**基板**里，意义在**关系**里；它是**超文本**，不是文档。

| | 笔记 | 文档（Word） | 文本 |
|---|---|---|---|
| 目的 | 捕捉思考 | 交付成品 | 承载字节 |
| 结构 | 涌现（链接长出来） | 预设（章节分页） | 线性 |
| 生命周期 | 永不完结 | 会完成/发布 | 无身份 |
| 关系 | 对其它笔记（图） | 对读者（呈现） | 对介质 |

**单条笔记没价值，笔记之间的图才是资产。**

---

## 2. 四要素

```
Node      节点   —— 可寻址的最小单位（= 一个块 / 稳定 OID）
Substrate 基板   —— 节点里装的内容：有序行序列 + 行内区间样式（正文）
Relation  关系   —— 节点之间的有向边：一等行，落 DB（不是块）
Composition 组装 —— 一种角色：正文里放节点引用的 note → 文档/博客
```

- **正文是行序列**（不是固定字段模式）：一行 / 一块一个元素，见 §6。
- **标题是描述字段**（`title`），不是正文的一部分；显示时也可由首行兜底。
- **没有链接语法**：链接是**独立的关系行**，不是正文里的语法糖；`[[ ]]` 只是创建关系的一种输入方式。

---

## 3. 身份与不可篡改性

- 节点身份 = 稳定 **OID**（ULID，创建即锁死），作为块存进桶（[`storage-design.md`](./storage-design.md)）。
- **本地不加密**：落盘明文，加密只用于传输 / 服务端（见 [`access.md`](./access.md)）。
- **创作签名**：`Signature{alg, author, created, subject, prev, value}`（`feature/signature.py`），
  创建时锁在当时的 `body.hash` 上；当前 `alg="b3"` 是自包含的哈希链（改任一字段 `value` 即对不上），
  日后换 `ed25519` 不破格式。它证明"原始结构可找回 / 未被改写"，不是网络身份。
- **不可篡改性由内容寻址保证**：`checksum = body_hash`（落盘负载哈希），读回重算校验。

## 4. 两种演化模式（关键）

笔记被改变分三类，规则不同：

### 4.1 作者自改（同一节点）

- 原件**必然变更**（块内容前进）。
- **保留"一点点版本路径"，不做 git 式全历史**：默认保留**最近 30 天时间窗**内的版本，
  超出即由压实裁剪（`VersionStore.compact(retention_ms=...)` 可调）。
- 版本走通用 `VersionStore`：`prev` 哈希链 + 反向补丁（按行 id）；顺序从 head 沿 `prev` 走。
- **版本只记内容**：只有**基板（正文 / 行内样式）变化**才追加补丁；标题 / 标签 / `props` 等
  元数据变更**不产生历史**。
- **保存 ≠ 版本**：连续编辑中的自动保存只**落盘**（`Note.persist`）；版本检查点在**非连续编辑边界**
  才产生——空闲超时（默认 5 分钟无编辑）、切换笔记、手动 `Ctrl+S`（`Backend.saveNow`）、退出（`shutdown`）。

### 4.2 协作修改（同一节点，多人）

- 类似 WPS 共同协作：多人对**同一节点**演进。
- 需要**多作者版本链** + 并发合并。
- **诚实边界**：真正的实时协作（CRDT/OT、冲突合并）是独立难题，**本阶段不做**；模型预留多作者署名，实现后置。

### 4.3 再发布 / 派生（新节点，跨作者）

- 类同开源：基于他人内容升级、引用、改写。
- **生成新节点 + `derived-from` 关系边**，署名派生者。
- **原件不受任何影响**（原件在原作者的库里，别人改不到）。
- 这正是**衍生关系**的来源。

## 5. 笔记衍生关系（Provenance DAG）

- 跨作者改写链（张 → 李 → 明 → 红）构成一张**派生 DAG**，与 git commit 图 / 学术引用图同构。
- 节点带创作 `Signature`（署名 + 内容承诺）；**关系行的作者 / 签名预留**（现在只记 `src / dst / kind / at / attrs`）。
- **贡献者** = 沿 DAG 回溯的作者集合。
- **原作者回溯** = 查 `dst = 本节点, kind = derived-from` 的传递闭包 → "谁基于我改过"。
- **阅览是隐私**：默认不追踪阅读；读者可**自愿**发 `read` / `endorse` 边，否则无从得知。

## 6. 基板（Substrate）：有序行序列 + 行内区间样式

> **已实现（M0，2026-09-17）**：`note/model.py` / `note/edit.py`。

```
body  = [ {"id": 行id, "v": "一行文字", "p": {"heading": 1}}, {"id": 行id, "v": {"canvas": n}}, ... ]
style = { 行id: [ {区间(tuple): Style} ] }
```

- **一元素 = 一行 = 一段**（硬回车是段落边界；软换行只是 UI 显示）。
- **`p` = 行级（段落）属性**（可缺省）：`align` / `heading` / `list` / `level` / `block` 等；序号等算得出。
- **行 id 稳定**（ULID，生成即锁死）：行增删 / 重排不影响样式与版本（无下标漂移）。
- **样式是叠加层，不是内容**：`{行id → 区间层}`；行内加粗只需加区间，不拆 body；后层压前层，
  规范化为不重叠、有序、去默认。
- **内容签名（`body.hash`）剥离行 id**：同文同样式即同签名（签名 / 版本用）；改一字即不同（`p` 计入）。
  **去重键 `checksum = body_hash` 按落盘负载算、含行 id**，避免不同行 id 的笔记串内容。
- **嵌入块**：图 / 视频 / 文件 / 画板都以占位元素表达，本体另存（`Asset` / `Canvas`）。
- **超长行**：等效中文 > 300 字（`OVERLONG_WEIGHT`）时由 UI 关软换行、转横向滚动（逼硬回车），
  并在空白处给「到行末」按钮；**内核不强制拆行**。

> 旧稿一度写成「文字块 + runs」；已按上表收敛为「行序列 + 区间样式」，不再另设 runs 字段。

### 6.1 手绘（sketch）：存原始笔画

- **自由创作必须保真**：sketch 存**笔画折线坐标**，不存栅格图。
- **识别（歪扭 → 标准图元）是可选增强**，不是保存前提——识别失败不导致数据丢失。
- **逻辑图（diagram）不走手绘**：它只存语义（节点 + 边），几何走自动布局（[`data-model.md`](./data-model.md) §5.3）。
- 识别引擎可为设备端小模型（见 §8），作为**单独的增强流程**。

## 7. 组装 / 投影（Composition）

- **组装不再是独立格式 / 物种**：它就是"正文里放一堆引用块"的 **note**（一种角色）。
- **文档 = 组装的 note**；**博客 = 公开档里的组装**；渲染是投影。
- 于是"写文档"与"发博客"共用同一模型，只是**可见性档位不同**（私密 / 公共 / 公开）。
- 笔记是原料，文档/博客是投影——直通 P2P 北极星。

## 8. Agent 与 AI

### 8.1 立场

- **AI 不是作者身份，而是一种"使用方式"**：用户通过 AI 调用能力。
- AI 的动作**归因于发起它的用户**（可标注"AI 辅助 / 用了哪个模型"）。
- 因此**不为 AI 单做一套 API**：把内核能力暴露为**可被调用的工具**（MCP / skill），AI 与人都走同一套。

### 8.2 内核能力即工具集

读（`open/iter`）、订阅（`subscribe`）、写（`put`）、建关系——天然就是一批"工具"。AI 接入 = 挂一个 Agent，按需调用这些工具并写回结果。

### 8.3 低能力 AI 与高能力 AI

| | 低能力 AI | 高能力 AI |
|---|---|---|
| 形态 | 自研机器人 / 规则引擎 | 大模型 Agent |
| 用途 | **规则性治理**：用户组合规则形成社区规则 | 帮助写作、整理、复杂治理 |
| 成本 | 低、敏捷 | 看谁有钱 |

- 社区治理是**未来 P2P 社区**的一部分，底层只提供"工具 + 关系"，治理逻辑属上层。

### 8.4 提案（proposal）

- Agent 可先产出**提案**（不落盘），人接受后才成为派生 / 关系。
- 保证"人在环上"，AI 不越权。

## 9. 捕捉面 vs 编辑面（及时性）

念头会过期，所以**捕捉必须零摩擦**：

| | 捕捉面 catch | 编辑面 develop |
|---|---|---|
| 时刻 | 念头一闪 | 坐下来整理 |
| 要求 | 秒开、零成本 | 富、慢一点无妨 |
| 技术 | 原生 Qt 外壳、常驻热键 | 富编辑 / 画布（分块渲染 + 行内样式） |

- 总体架构：**Qt 外壳（窗口 / 列表 / 搜索 / 热键捕捉 / 时间轴）+ 富编辑画布**，两者分离。
  界面**待重建**（旧 QML 已删；`ui_tools` 工具箱 + `src/app` 载体）；Web 富编辑（QtWebEngine）为备选路线，未引入。
- 正文原语在 `note/edit.py` / `note/types.py`（行级编辑 + 行内样式 + 占位，见 §6）；**编辑器 UI 待重建**。
  待迭代：跨行选区、撤销/重做、样式工具栏。
- 首期入口：**从文档（组装）角度切入**——先能"写文档"，再补"闪现捕捉"。

## 10. 与内核的映射

| 概念 | 内核落点 |
|---|---|
| 节点 | 块（`type = notedata`），稳定 OID；创作 `Signature` 记署名 |
| 基板 | `NoteBody`：`text`（行序列）+ `style`（行内区间样式）；`note.style` 代理 `body.style` |
| 去重签名 | `checksum = body_hash`（落盘负载哈希、含行 id）；剥离行 id 的内容签名是 `body.hash` |
| 关系 | **由块自己表达**（块说它有哪些关系）；库只做索引，**索引尚未设计**（不预埋） |
| 组装 | 角色：正文里放节点引用的 note |
| 版本路径 | 通用 `VersionStore`（`prev` 哈希链 + 反向补丁），域提供 Codec |
| 衍生关系 | 对块表达出来的关系做闭包计算（索引形态待设计） |

关系类型（草案）：`derived-from`、`edits`、`annotates`、`replies-to`、`references`、`transcludes`、`read`、`endorse`。
哪些真的用得上，等有领域产生关系时再定——**现在不预埋**。
