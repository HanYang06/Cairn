# 访问策略与 P2P 预留（Access & P2P）

> 承接 [`storage-design.md`](./storage-design.md)。定义**可见性档位**、密钥分发、信任根，以及为 P2P 预留的接口。
> 立场：**威胁模型不做全域防御，只收敛为有限几档，逐档配对等的密钥机制。**

状态：**草案 v0.2**——**仅为传输 / 服务端加密的方向设计**，未实现。
前提：**本地落盘明文、没有"空间"这一持久概念**（见 `storage-design.md` §9.5）；因此本文的
「空间」一律指**分享策略层**（`Audience` / `ShareKind`，**预留**——该策略层尚无代码），
不是存储结构。落地前需整体复核。

> **2026-09-19**：本文为**传输 / 服务端**方向的预留设计，**未实现**；原实验顶层包 `src/net` / `src/server`
> 已删除，落地时按需重设。本地落盘明文（见 `storage-design.md` §9.5）。

---

## 1. 一句话模型

> 存储是数据流，传输也是数据流。对象默认私密；**分享目标是策略层的一组标签**
> （个人主页 / 社区 / 某人），据此决定可读范围、可发现范围与密钥交付方式。本地不做加密。

---

## 2. 四档可见性

| 档位 | 谁能读 | 谁能发现 | 密钥机制（仅传输 / 远端） | 去重范围 |
|---|---|---|---|---|
| **私密** private | 仅本机 | 无人 | 外发副本用随机 CK | 本库内 |
| **公共** communal | 网络成员 | 网络内 | **共享密钥**：组密钥，wrap 到成员 X25519 | 网络内 |
| **公开** public | 任何人 | 任何人 | **公开密钥**：已发布/非秘密，或明文 | 全局（可公开哈希） |
| **定向** direct | 指定对端 | 双方 | 每对象 CK，wrap 到收件人 X25519；或 PSK | 基本无 |

要点：

- **本地一律明文**：上表密钥机制只作用于**传输 / 远端副本**，本机桶内不加密（`storage-design.md` §9.5）。
- **公共 ≠ 公开**：公共的密钥仅成员持有（共享密钥）；公开的密钥或明文任何人都可能获得（公开密钥 / 明文）。
- 去重边界 = 明文 / 密钥可见范围：本库内按 `body_hash` 去重；跨节点只在能共享明文的范围内去重，
  **不会**因加密产生跨档确认攻击。
- 档位是**策略**，可随时在受控条件下升降级（涉及重加密，见 §6）。

## 3. 身份与信任根

### 3.1 身份

- 每库一对密钥：**Ed25519**（签名，作者证明）+ **X25519**（密钥协商，接收封装）。
- 公钥即网络标识（peer id = 公钥短哈希）；私钥种子由 MK 封装，解锁后可用。

### 3.2 信任根

- 块的创作 `Signature` 承诺其 `body.hash`；签名值形态（`alg` / `prev` 哈希链）见
  [`note-model.md`](./note-model.md) §3。**签名能力预留、尚未实现**（原 `feature/` 层
  已随 2026-09-29 的重建删除）。
- **版本链归领域，存储不提供**（`storage-design.md` §9.1、§10：版本引擎 / 保留窗已裁剪）；
  `prev` 链属领域层预留设计，未实现。
- 传输身份用 **Ed25519**（签名）+ **X25519**（协商）——**未来接入 P2P 时引入**，本地不需要。
- 对端同步时按**验签 → 验链 → 应用**的顺序执行，任一不通过即拒收该版本；该流程随签名与
  版本链（均预留）一并落地。
- 信任启动：首次获取某作者公钥的途径（扫码/邀请/介绍人）待定，属发现层。

## 4. 密钥分发（按档位）

### 4.1 私密

- SK 随机生成（**仅传输 / 远端副本用**）；本机落盘明文，不封装密钥。

### 4.2 公共（共享密钥，成员可读）

- 组密钥 SK 分发给成员：对每个成员的 X25519 公钥，用 **ECIES 式封装**（临时 X25519 → HKDF → AEAD 包住 SK）。
- 成员变更 → **密钥轮换**：新 epoch 的 SK 只加密新写入；旧 epoch 密钥按需重封装（懒轮换，见 §6）。
- 分享策略记录（规划）本身只含"封装后的 SK + 成员列表"；不持有 SK 者无法解密内容。

### 4.3 公开（公开密钥，任何人可读）

- SK 为**公开密钥**（可发布、可从公开种子派生）或内容直接明文。
- 目的：承载可公开发布的博客 / 站点内容；且公开空间可**全局去重**（同内容全网一份）。

### 4.4 定向（点对点）——双机制并存

- **默认·非对称封装**：每对象随机内容密钥 CK；用收件人 X25519 公钥封装。无需预先共享秘密，可对多人分别封装。
- **可选·预共享密钥（PSK）**：双方提前约定口令/分享码，`Argon2id(口令) → KEK` 封装 CK。
  - **PSK 的代价**：**无前向保密**；口令弱则可离线暴力破解；密钥复用/泄漏影响面大。故 PSK 定位为**便捷分享手段**，非默认。
- 定向发送一个属于私密空间的对象时，需**重打包**（把明文用 CK 重新加密进"定向空间"）；代价是该副本不参与去重，可接受。

## 5. P2P 预留（数据面）

数据面的协议细节以 [`network.md`](./network.md) §3 为事实源（want / block / meta 的流程与校验顺序），本节只保留与存储的对应：`checksum` 即内容地址，"一组 checksum"是最小传输原语；大内容的分片块 + 索引块构成可分段、可续传的流；增量按内容哈希只传缺失块；分享目标是授权与去重的单位（公开内容可全局去重，公共内容网络内去重）。块签名与 `prev` 链**预留**（签名与版本链未实现，见 §3.2）；发现 / 传输 / NAT 穿透 / 同步与冲突合并属未决项，见 `network.md` §5、§10。

## 6. 密钥轮换与档位变更

- **轮换（空间内）**：引入 **key epoch**。块记录其 epoch；新写入用新 epoch 密钥；旧 epoch 密钥保留以读旧块，按策略懒重封装或重加密。
- **档位变更**（如 私密→公共）：
  - 升"更公开"：把 SK 以目标档位方式重新分发（如 wrap 给成员），块无需重加密。
  - 降"更私密"：**必须重加密**（旧密文/已分发密钥无法收回），生成新 SK 并重写块。
- 明确：**已泄漏的密钥无法追回**，只能靠轮换限制后续影响。

## 7. 威胁模型（收敛）

承诺覆盖的范围：**传输侧与远端副本**——中间人截获由内容 AEAD 与"密钥不经明文信道"防御；
内容篡改由 AEAD tag + `checksum` 重算 + 块签名（签名预留，见 §3.2）检出；非成员窥探公共内容由
共享密钥仅成员持有来防御；假冒作者由签名与版本链（均预留）防御。**明确不防**：本地磁盘
（落盘明文，`storage-design.md` §9.5）、解锁态终端被攻陷、弱口令离线暴力、已授权成员的二次泄漏、
组密钥轮换前的旧密钥仍可解密旧数据。流量元数据（谁连谁、传多少、何时）与默认不广播清单等
更广的隐私边界，以 [`network.md`](./network.md) §9 为事实源。
