# 架构文档索引

> `docs/architecture/*.md` 是设计事实来源。两条前提：
> **① 每篇都标了状态；② 与代码冲突时以代码为准**。

## 权威顺序

```text
代码  >  docs/architecture/<具体篇>  >  docs/architecture/<总纲篇>  >  记忆 / 其它
```

- 架构文档是对现状与方向的描述。改了实现就回写文档；回写是任务的一部分。
- 标「草案」的篇目表示方向已定、部分未实现；标「预留」的表示只有方向。
  **凡标「预留 / 草案 / 待定」的内容，不作为实现依据。**

> **取代关系**：本次裁定改写的存储页有 [L0 存储设计](storage-design.md)、
> [载体的字节布局](py_core/storage/pack-format.md) 与[查询链路](py_core/storage/query-path.md)；
> 与[块的组成与落点](py_core/storage/block-parts.md) 冲突处以该篇为准，差异清单见其 §9。

**内核装配（`Kernel`）与命令面（`Api`）的现状口径写在 [L0 存储设计](storage-design.md) §9**，
不再单开一页：那一层只有"接一根线"与"一张方法表"两件事，另开一页必然与 §9 各说一套。

**事件层的现行口径**：事件只做扇出通知，不做决策——内核中没有事件解析器，
也没有「解析包 → 决定做什么」的中介者。事件对象与总线在 `py_src/core/event/`，
目录只有两条（`object.put` / `object.deleted`），以 `core/event/catalog.py` 为准。
**订阅只发生在事件日志这一处**（`core/event/logs.py`）：一次订阅、按分流表走
诊断 / 落盘 / 反馈；落盘是一份追加写的文本记录，不算进存储（详见
[L0 存储设计](storage-design.md) §9.3）。
