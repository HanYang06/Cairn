# 架构文档索引

> `docs/architecture/*.md` 是设计事实来源（design source of truth）。两条前提：
> **① 每篇都标了状态；② 与代码冲突时以代码为准**（`AGENTS.md` 红线）。

## 权威顺序

```
代码  >  docs/architecture/<具体篇>  >  docs/architecture/<总纲篇>  >  记忆 / 其它
```

- 架构文档是对现状与方向的描述。改了实现就回写文档；回写是任务的一部分。
- 标「草案」的篇目表示方向已定、部分未实现。凡标「预留 / 草案 / 待定」的内容
  不作为实现依据。

**事件层的现行口径**：事件只做扇出通知，不做决策——内核中没有 `EventParser`，
也没有「解析包 → 决定做什么」的中介者（理由见记忆的「事件层只做扇出通知」）；
事件对象与总线在 `py_src/core/event/`。
