# 配置引擎

> 状态：**现行**（2026-09-30 落地）。
> 事实源：`src/core/conf/`（引擎与 `conf` 面）＋ 各包自己的声明模块（`core/conf/params.py`、
> `core/storage/conf.py`）；本文件是**用法契约**，形状与注意事项同时写在代码的 docstring 里。

## 1. 一句话

**一个 `conf` 面、一种调用形、一份单文件投影**。声明与取值是同一个调用，差别只在给不给参数；
写只记一笔、退出时统一落盘；跑一遍程序，值文件与词表就都生成好了——**没有专门的生成脚本**。

```python
from core.conf import conf

conf("storage.pack.slot_bytes", 65536, type=int, doc="槽长")  # 声明
slot = conf("storage.pack.slot_bytes")  # 取值
```

"无孔不入"说的是**使用点**：import 之后任何地方都能直接用，脏活（定位、缓存、补缺、落盘、
词表）全在 `conf` 背后。附带的好处是**全仓只扫 `conf(` 这一个词**就能列出全部使用点——
声明与取值都不隐身，"谁在用配置"有确定答案。

## 2. 声明与取值：同一种调用

| 写法 | 含义 |
|---|---|
| `conf("a.b", 默认值, type=…, doc=…)` | **声明**（第一次写进值文件） |
| `conf("a.b", type=…, doc=…)` | 声明一个**没有默认值**的项（值必须由文件给，丢了报错） |
| `conf("a.b")` | **取值** |

参数：`path`（点分键）／`default`（默认值）／`type`（类型）／`doc`（写进词表，IDE 悬停可见）／
`file`（值放独立文件，见 §6）／`force`（强写，见 §4）。

**声明是唯一事实来源**：默认值只写在声明处，实现里不抄第二份（存储那组直接引用
`hub.DEFAULT_SLOT_BYTES`，就是为了让"一份事实、两处引用"而不是抄一个数字）。

## 3. 事务：引擎自己组织，调用方不划批次

```python
conf("core.log.level", "INFO")
conf("storage.pack.slot_bytes", 65536)
```

写侧**只记一笔待写、立即返回**（所以写的体感与读一样快）；到该落盘的时刻才做完整轮：
读旧值 → 补缺失键 → 一次写盘 → 词表重算一次。

**为什么不提供 `with conf.scope()`**：局部看是"小事务"，整体看调用密度很高，批次边界由调用方
手划既不自然、也会漏（漏一次就退化成一次落盘）。更要紧的是——这一层的写操作**幂等且无序**
（只补缺失、不改已写），任何一批的子集、超集、重排落盘结果都合法，**批次因此只是减少 IO 的
优化，不是语义边界**。既然不承担语义，就不该在接口上出现。

批内读得到待写值：`conf(k, v)` 之后再 `conf(k)` 一定拿到 `v`（引擎维护待写覆盖），
否则"写完立刻读读回旧值"就自相矛盾。

## 4. 落盘的四条通路

| 通路 | 做什么 | 谁用 |
|---|---|---|
| **默认** | 只记一笔，进程退出时统一落盘（`atexit`） | 日常写法 |
| **`conf.sync()`** | 把攒着的都刷掉（值文件 + 词表），并交出新增 / 改动的键 | 测试、工具、要"文件此刻就是对的"的场合 |
| **`force=True`** | 单键强写：**不许攒着**（立即落盘）＋ **允许覆盖已有值** | 显式改值 |
| **退出保底** | 同上第一条，进程正常结束时执行 | 无需调用 |

`sync()` 是"把攒着的都刷掉"，`force` 是"不要把它攒着"——两条共用同一段落盘代码。

**注意事项**（影响都不大，故写在这里而不是铺一篇设计）：

- **默认不即时**：崩溃丢的是"还没落盘的那几笔"。这不是数据事故——声明写死在代码里、
  已落盘的值一个字节没动，重启即可恢复；**文件永远不含错东西，只会比预期旧一个版本**。
  真丢得掉的只有"文件里没有、代码里也没声明的键"，那本来就不算数。
- **只读盘写不出去不报错**：值文件是投影，写不出去不影响本次运行；读值也不依赖"先写成功"。
- **值文件缺失 / 陈旧不是错误**：缺了按声明重建，旧了只补缺失的键。
- **词表不会因为"没加载到声明"而被清空**：一个只 import 了部分模块的进程不会把整份词表写成空对象。

## 5. 写入方向单向：代码 → 文件

```python
conf("core.log.level", "INFO")  # 声明（第一次）
conf("core.log.level", "DEBUG")  # 报错：已经有值了
conf("core.log.level", "DEBUG", force=True)  # 强写：就改
```

作者口径：**写入任务只有两种**——建无数值的项、建有默认值的项；其余只能是**读取**。
**改值只从配置文件改回来**（人编辑文件是改值的正路），除非显式开强写。

这一刀拿到两样：

1. **重复声明在启动时就炸**，报错发生在**调用点当时**（不是两次静默覆盖，也不是攒到落盘才炸），
   并带上先声明那一处的出处（文件名 + 行号），免得只知道撞了、不知道撞的是谁；
2. **用户手改的值天然受保护**——代码手里的默认值顶不掉文件里的改动，想顶必须自己写
   `force=True`，责任在明面上。

判据是"**本会话已经声明过**"，不是"文件里有这个键"：否则删掉值文件里的键再补回来会撞上自己的口径。
用户自己加的键（登记表没见过的）**永远留着**——引擎只补缺失的键、不删不改别人的东西。
"曾声明、后已删除"的键则会随下一轮落盘消失（它既不在登记表里、也不算用户加的）。

## 6. 类型：由形参给，声明期就校验

```python
conf("storage.pack.slot_bytes", 65536, type=int, doc="槽长")
conf("ui.zoom", 1.0, type=float)
```

- **判等用 `type(v) is T`，不用 `isinstance`**——`isinstance(True, int)` 为真，但 `bool` 与 `int`
  在 JSON 里是两个东西，`type=int` 配 `True` 必须拦下；
- **唯一放宽的是 `int` 值配 `float` 类型**（无损提升），且放宽后**按浮点算**：
  默认值 `65536` 会落成 `65536.0`，否则读回来是整数、会自己把自己拦下；
- 反向（`type=int` 配 `1.5`）一律报错，哪怕值是整数值的浮点也不放行；
- **类型必须落在 JSON 能表示的那几种里**：`int` / `float` / `bool` / `str` / `list` / `dict`，
  可带一层元素（`list[int]` / `dict[str, int]`），外加 `None`。`bytes` / `datetime` / `Path` /
  枚举 / 元组 / 集合在声明期就拒——不是洁癖，是"校验过得去"的前提；
- **读写两侧同一套判据**：人手改坏文件同样是当场报错（声明那一刻就查），不静默当另一个类型用；
- 省略 `type=` 时按默认值自身的类型判。

静态类型：声明处返回绑定的 `TypeVar`（所以 `x: int = conf("a.b", 1)` 与
`conf("a.b", 1).bit_length()` 都成立、默认值给错类型也能被静态抓到）；取值处没有注解即 `Any`。
**边界如实记**：静态检查抓不到"字符串键写错"，也不做"键 → 类型"的全局推导。

## 7. 文件引用：值放独立文件

`file="yaml"` 让这一项的值放进独立文件，默认**同层级的 `<字段名>.<类型>`**：

```python
conf("some.key", "", type=str, file="yaml")  # 值文件里那一行是 "some.yaml"
```

引用名由声明处算出来（不取默认值），且**不许跑出配置根**；被引用的文件必须已经在那儿——
声明期就报错，不等读的时候才发现。值文件里那一行是**事实而非装饰**：改成别的相对引用即换文件。

**能力在，内核当前没有用它的键**：表声明（`config/tables.yaml`）曾经走这条引用
（`storage.db.tables`），2026-09-30 起改成**由代码写出来的固定文件**——它由代码写、又被代码读，
不是"可以调的一个参数"（见[存储设计](storage-design.md) §8.2.1）。文件名是
`registry.TABLES_FILENAME` 这个常量。

## 8. 投影：两份产物，跑一遍就生成

```
config/settings.json          ← 值（用户可改；顶部 $schema 指向词表）
config/schema/settings.json   ← 词表（给 IDE 悬停与分发看的 JSON Schema）
```

- **键逐字保留点分形式**（`"storage.pack.slot_bytes"` 是一个属性名，不展开成嵌套对象）：
  `conf("…")` 里那个字符串是全仓唯一的检索词，代码与文件逐字一致，`grep` 才扫得干净；
- **没有生成脚本**：两份产物由引擎在落盘时写出，跑一遍程序（或 `pytest`）就顺带生成。
  入库的产物与声明是否分叉，由 `tests/core/test_conf_projection.py` 拦；
- 词表带 `type` / `description` / `default` / `x-cairn-owner`（声明它的模块）/ `x-cairn-site`
  （声明处的文件与行号）；`docs/reference/config.md` 由 `tools/docgen.py` 从**声明现算**渲染，
  不读入库的那份副本。

## 9. 边界（别越界）

- **各管各的**：谁要用配置，谁在自己包里声明（存储参数在 `core/storage/conf.py`，内核自己的在
  `core/conf/params.py`）；配置端只负责展开与取值，不替别人管；
- **格式常量不进配置**：载体魔数、文件头长度、记录头布局这类改了会坏库的，留在实现处；
- **已落盘的东西不被新配置改写**：槽长写进载体文件头，此后按文件头读；
- **引擎不依赖第三方**：只用标准库＋`core.exc`；
- **环境旋钮 `CAIRN_CONFIG` 不是配置项**：它是"找到配置的办法"（测试与部署重定向），
  值文件里不会出现它。

## 10. 未做（如实记）

- **"流写" / 定时窗口落盘暂不做**：它把"何时落盘"从"进程退出"再添一处，而真需要"此刻就是对的"
  的场合有 `force=True` 与 `sync()` 就够。**重启条件**：出现"长驻进程且外部读者要持续看到较新
  文件"这种需求再论；
- **不做"值来自声明还是用户改过"的来源标记**：只按"文件里有没有这个键"判，故用户把值改回默认
  值后这一笔的"改过"记录就丢了。现有需求不要求记住来路；
- **值投影仍是单文件**（十万行以内不分）：真要分，得先有量级，再谈坐标；
- **手写口 / 多来源合并**（个人覆写、部署覆盖）未做；
- `config/tables.yaml` 是表声明的**本体所在的那份文件**，但**不走配置键**：它由类型登记现算、
  由代码写出来（见[存储设计](storage-design.md) §8.2.1），故不在标量配置里占一个键。
