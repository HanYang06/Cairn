## 1. 目标与约束

- **好看**：**浅色优先**（笔记与项目管理以阅读书写为主，见 §3.1）、留白、克制动效，
  呼应品牌（冷灰石 + 暖赭 + 苔绿）。**深色保留为可选项**，跟随系统并可手动覆盖。
- **可控**：外观只来自令牌；**不引入会污染许可证的重框架**（前端生态尤需警惕，见 §4）。
- **快**：捕捉面（热键）必须即时可用，不承担前端启动的等待。
- **可维护**：主题以**令牌**集中管理，不散落在各组件里。

## 2. 令牌：外观的唯一真源

组件**只引用令牌**，禁止在组件内写死颜色 / 间距 / 圆角。令牌分五族：

| 族 | 内容 | 取值 |
|---|---|---|
| **色** | 背景 / 面板 / 边界 / 文字 / 强调 / 状态 | 见 §3（深浅两套） |
| **圆角** | `xs` / `sm` / `DEFAULT` / `lg` / `xl` | 3 / 6 / 8 / 10 / 12 |
| **间距** | `xs` / `sm` / `md` / `lg` / `xl` | 4 / 8 / 12 / 16 / 24 |
| **字** | 字体链 / 字号 / 行高 | 见 §3.2、§3.7 |
| **动效** | `instant` / `fast` / `base` / `slow` | 0 / 120 / 180 / 260 ms |

- **一套令牌，两套值**（深 / 浅）：组件只引用令牌，切换主题即换值。
- **留白优先**；强调色克制，只用于选中、链接、主按钮。
- **动效只做功能性**（淡入、位移），不做装饰性效果；提供"减少动效"开关（§6.7）。
  交互反馈的时长上限见 §3.5；阴影与圆角见 §3.3（已冻结）。

### 2.1 落地机制：**已定**

`config/theme/tokens.json` 是**唯一手写处**；`app/scripts/gen-tokens.mjs` 由它生成
`app/src/styles/tokens.css`（入库、**不许手改**）；防漂移走 `pnpm -C app check:tokens`
（并入 `pnpm -C app check` 七道门禁）。
深浅两套由 `prefers-color-scheme` 切换，生成器保证两套的键完全一致。
（Qt 时代的 QML 令牌单例与 QSS 编译**随 Qt 作废**。）

**同一套令牌也管文档站**（2026-10-10 补）：`docs/stylesheets/cairn.css` 把上表的值按同名搬到
`--cairn-*`、再映射到 Material 的 `--md-*` 变量，由 `mkdocs.yml` 的 `extra_css` 引入。
两处取向一致，故文档站与桌面界面**共用一套设计语言**（纸面底、暖金强调、弱边界、柔阴影、
圆角随尺寸走）：Material 的 `default` 档取浅色值、`slate` 档取深色值，两档都要写全，
漏写的那档会退回它自带的色。**改令牌要同步 `cairn.css`**——规则见
`.agents/skills/rules/references/docs.md`「文档站自己的外观」（仓库文件，不在本站）。
站点不用 Google Fonts：`--md-text-font-family` / `--md-code-font-family` 指向前端的字体链（§3.7）。

## 3. 品牌主题（结合 logo）

### 3.1 色板（令牌；**2026-09-30 按 logo 取色重定，且浅色优先**）

```
                            深色        浅色        用途
  bg         背景          #0D1117     #F7F5F2     纸面（**浅色底不取纯白**，见下）
  chrome     外框/标题栏   #010409     #F7F5F2     与纸面同色：外壳与工作区连成一片
  surface    面板          #0D1117     #FFFFFF     卡片 / 面板 / 编辑区
  elevated   浮层          #161B22     #FFFFFF
  border     边界          #30363D     #D8D5D0
  borderFaint 弱边界       #21262D     #E6E3DE     分区线（比 border 更轻，不抢注意力）
  text       正文          #E6EDF3     #1F2328     ← 主要阅读对象
  muted      次要文字      #8B949E     #57606A     ← 元信息、标签
  faint      弱文字        #6E7681     #6E7781     ← 时间戳、占位、禁用
  accent     强调（暖金）  #EDB761     #8A5F22     ← 唯一光源：选中 / 主按钮 / 焦点
  accentHover 强调悬停     #F4C87E     #A9752B
  accentAlt  次强调（绿）  #3FB950     #1A7F37
  accentText 强调上的字    #241A08     #FFFFFF
  selection  选中底        #3B2C13     #F3E7CF
  hover      悬停底        #161B22     #EFECE7
  danger     危险          #F85149     #CF222E
```

**浅色优先（2026-09-30 作者定）**：本文此前把深色当默认，**理由从未写下**，故按需求推翻。

1. **产品的底色要跟产品做的事走**：Cairn 是**管项目、写笔记**——阅读与书写的总时长压倒一切。
   对照行业：笔记与写作工具默认亮色，深色是**可选项**；深色当默认的是终端、代码编辑器那一类。
2. **纸面不取纯白**：`#F7F5F2` 的亮度比纯白低约 **8.5%**——足以减眩光，又不到"显黄"的程度。
   于是同屏形成**三级明度**：纸面（工作区底）→ 面板（白，放内容）→ 浮层（白 + 阴影）。
   正文对纸面 **14.52**、对面板 **15.80**，均远超 AA。
3. **深色保留为可选项**，跟随系统并可手动覆盖（§6 的"显示"入口）。
4. **两套都是一等公民**：生成器保证两套键完全一致，`app/tests/tokens.test.ts` 断言
   **正文与强调色对各自背景都过 AA**——加了色就得过门禁。

**强调色为什么是暖金（有据可查，不靠感觉）**：

1. **石头是冷的**：从 `assets/logo/png/cairn-256.png` 逐像素取色，暗部石头 `#0E1319`
   （R−B = −11）、受光石头 `#3A434C`（R−B = −18）——**中性色本来就是冷灰蓝**；
   现行的 `#0D1117` 与之同族，**故深色底不动**。
2. **光是暖的**：logo 里唯一的暖色是阳光擦过石棱的 `#EDB761`（R−B = **+140**）。
   **故强调色由冷蓝改为暖金**——冷石 + 一道暖光正是 logo 的结构；
   冷暖相对，暖金自然成为画面里唯一的光源。**张力由此而来，不靠把底色改暖。**
3. **一色值一样本**：深色 `#EDB761`（对 `#0D1117` 对比度 **10.41**）、
   浅色 `#8A5F22`（对 `#F7F5F2` **5.16**）——均过 WCAG AA；
   原金在浅色底只有 1.82，**故浅色不用原金**。
4. **中性色仍然参照 GitHub Primer**；并保留 `borderFaint` / `faint` / `hover` /
   `accentText` 与高对比覆盖（§6.7）。
5. **三级文字形成层级**：正文 / 次要 / 弱，浅色下分别约 14.5 / 5.9 / 4.2——
   这是界面"层次感"的来源，不靠加边框。
6. **边界刻意弱**：`border` 对底仅 1.34–1.46 的对比——**边界不该是重点**，
   辨识靠留白与明度分层；需要明显之处使用 accent。

**待定**：品牌 mark 的浅色形态（logo 是深底暖光，浅色主题下需要一份反相或描边版本）。

### 3.2 字号阶梯（参照 VS Code 的克制）

**阶距可辨而不突兀**（参照 VS Code；判据为"偏移过大时观感不适"）：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--fs-2xs` | **11px** | 时间戳、计数、角标、快捷键提示 |
| `--fs-xs` | **12px** | 元信息、命令带、列表副行、检查器 |
| `--fs-sm` | **14px** | **界面正文**：列表项、标签、输入 |
| `--fs-md` | **17px** | 内容正文（编辑区）、卡片标题 |
| `--fs-lg` | **20px** | 面板标题 |
| `--fs-xl` | **26px** | 页标题 |
| `--fs-2xl` | **36px** | 展示（空态标题、聚焦态标题） |

- 行高三档：`tight 1.2`（标题）/ `DEFAULT 1.5`（界面）/ `snug 1.65`（正文）/
  `loose 1.9`（**专注写作**：行距是写作舒适度的第一变量）。
- **`sm = 14px` 是界面正文**，不是 13px：13px 与 12px 间距过小，层级趋于平均。

### 3.3 阴影与圆角（**已冻结**）

口径（2026-09-30）：**阴影与圆角已冻结，此后变更仅按下方三条机制进行。**
二者管的是**全体组件**的共性观感，**稳定性优先于小幅观感改善**。

**口径一句话**：**不夸大、不放任，但必须看得出来、感觉得到柔。**

| 判据 | 落地 |
|---|---|
| **不夸大** | 阴影不许把内容压下去（核对稿里"太重"那一档即反面） |
| **要柔** | **两层**：小偏移那层勾出边缘，大模糊那层给柔感——**单层做不到**（要柔就糊、要清就硬） |
| **看得出来** | "柔"指**能被感知的柔**；柔到看不见等于没有（"太扁"那一档即反面） |
| **棱角不能硬** | 圆角**随尺寸走**：够不够柔不只看数值，还看**与元素尺寸的比例**——3px 落在大卡上就是硬 |

> **为什么"硬"要避免（可复用的一条设计原则）**：
> 扁平 / 硬棱角当年成立，是因为**渲染能力就只能那样**（作者口径："当时确实没这个技术"）。
> 于是判据是：**凡"当年只能这样"的视觉习惯，技术成熟之后就该改；不改即是负分**——
> 会被理解为"没做"或"复古"。本条可外推到硬边框、纯色块、无状态过渡等同类做法。

**阴影取值（只有三档，且深色用更深的黑）**：

| 令牌 | 用在哪 |
|---|---|
| `--shadow-sm` | 悬停浮起、下拉、工具提示 |
| `--shadow` | 弹出层、菜单、命令面板 |
| `--shadow-lg` | 模态、独立窗口、拖拽中的卡 |

取值见 `config/theme/tokens.json`（双层：一层贴边小偏移 + 一层大模糊）。
**深色主题的阴影必须比浅色更重**——新版本按此取值（旧的 `rgba(0,0,0,.08)` 在深色底上几乎看不见）。

**圆角取值（五档，按"层级"分派，不按"好看"）**：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--radius-xs` | 3px | 标签、角标、选中指示条 |
| `--radius-sm` | 6px | 小按钮、输入框、列表项悬停底 |
| `--radius` | 8px | 面板、卡片、按钮 |
| `--radius-lg` | 10px | 浮层、菜单、弹窗 |
| `--radius-xl` | 12px | 卡片工作台里的卡、模态 |

**规则**：**外层半径 ≥ 内层半径**（嵌套时内层不能比外层更圆），否则嵌套层级在视觉上倒置。

**对齐口径（2026-10-10 补，两条都算"硬"的反面）**：

1. **同级的左沿只有一条**：一个容器里，节标题、列表项、子项**文字左沿必须落在同一列**。
   缩进用"这个元素属于谁"表达（节标题管一组、子项属于它），**不得**用"把文字再往右／往左推
   几像素"表达。判据可量：**各层文字左沿偏差应为 0**（文档站侧的实测值见下）。
2. **层级由结构表达，不由数值表达**：父项只是节名、子项才是链接时，两者的文字左沿一致；
   层次靠分组间距与字重区分（与"外层半径 ≥ 内层半径"同族——层级由结构表达）。

> 这条的来历（**踩过两次，故把实现方式一并记下**）：文档站侧栏加悬停胶囊时，
> 第一版给 `.md-nav__link` 加了横向内边距——那改了盒模型，Material 算好的各层对接随之错位
> （实测：节标题 `x=16`、子项 `x=8`）；第二版又在子项上"再抵一次"负外边距，方向反了，
> 成了子项比节标题更靠左。
> **正解是文字的 x 一动不动，只把底色往外扩**：`.md-nav__link` 的横向内边距归零、
> 用等量负外边距把悬停底色撑出左沿。故改侧栏样式时**先量 x 再动手**，
> 别拿"看着差不多"当判据。

**冻结机制的三条（怎么加，而不是"不许动"）**：

1. **档位只增不改**：新组件确实放不进现有档时**加一档**，**不动老档**——
   老档一改，全仓组件的观感同时漂移。
2. **要改得带功能性证据**：视觉偏好不算数；**对比度不达标、某场景下阴影确实看不见**
   这类才算。改动记进本文与记忆的变更记录。
3. **试验值不许进令牌**：探索阶段可随意试，但**不得塞进 `config/theme/tokens.json`**；
   定了才进。避免令牌表充当草稿条目、档位累积而无从判断哪档生效。

核对稿（三档阴影正反面 + 圆角随尺寸的比例）：`.design-lab/comp.html`（不入库）。

### 3.4 按钮与动作层级（胶囊的边界）

作者倾向**胶囊按钮**；把它落成有边界的规则，否则会全场景滥用：

| 层级 | 形态 | 用在哪 | 一屏数量 |
|---|---|---|---|
| **主操作** | 胶囊 · 实心（`accent` 底 + `accentText`） | 保存、新建、确认 | **最多 1 个** |
| **次级操作** | 胶囊 · 幽灵（无底、悬停才出 `hover` 底） | 命令带、工具栏 | 不限 |
| **不可逆操作** | 胶囊 · `danger` 文字 | 彻底删除、清空 | 就近 |
| **列表 / 菜单项** | **矩形**（`radius-sm`） | 列表行、右键菜单项 | — |
| **容器类** | **矩形**（`radius` 及以上） | 卡片、面板、输入框 | — |

**判据一句话**：**动作可以是胶囊，容器不做胶囊。**
代价是行高变高、同屏能放的动作变少——**此为预期代价**（见 §3.5 的单动作原则）。
图标按钮同样圆，但**必须配悬停提示**（§6.11）。

### 3.5 单动作与动效上限（作者口径）

> **UI 不是越复杂越好、颜色不是越多越好；清晰、简单、单一动作就够。**
> **UI 动作越多越丑。**

由此三条：

1. **一屏一个主操作**（§3.4 已落成规则），其余一律幽灵样式或收进右键菜单。
   **能用右键菜单的，就不搬到界面上。**
2. **不做过程动画**：切换就是切换，**不加中间过程**（不做过场、不做叙事式转场）。
   依据是作者的判断：**连贯动画要有叙事支撑，而 UI 本身承载不了叙事**，
   于是中间过程只剩带宽成本与等待。
3. **交互反馈的时长上限 = `--dur-base`（180ms）**：悬停 / 按下 / 展开用 `fast` 或 `base`；
   `slow`（260ms）只给"位移较大"的展开收起。
   **悬停与选中一律即时**（不做颜色过渡，避免相邻项交叉淡入被看成"同时高亮两项"，§6）。

**唯一豁免**：启动画面与进度反馈——它们是**状态**，不是叙事。

### 3.6 其余规范

- **字体**：中英统一**等宽字体链**（见 §3.7 的许可证与体积结论、§3.8 的替换机制、§3.9 的"不花"判据）。
- **图标**：单色线性，随文字色染色；前端侧为 SVG 图标组件（图标集来源待定，先核许可证）。
- **圆角与间距**：见 §2 的令牌表与 §3.3。

### 3.7 字体：许可证、体积与现状

**一手结论（2026-09-30 核实，均读许可证原文）**：

| 字体 | 许可证 | 中文 | 结论 |
|---|---|---|---|
| **Sarasa Gothic / 更纱黑体** | **SIL OFL 1.1**（[LICENSE 原文](https://github.com/be5invis/Sarasa-Gothic/blob/master/LICENSE)，含 Inter / Source Han Sans 第三方段落） | 有（`Sarasa Mono SC` 等） | **可用**：可打包、可嵌入、可随软件分发；**不得单独售卖**；须随附许可证与版权声明 |
| **Maple Mono（含 CJK 构建）** | **SIL OFL 1.1**（[README](https://github.com/subframe7536/maple-font) 明示） | 有（`CN` 构建，CJK 默认**不构建**） | **可用**，同一套 OFL 义务；圆角风格、中英 2:1 宽比 |
| 系统字体（`Segoe UI` / `Microsoft YaHei` / `Consolas` 等） | 随 OS 授权 | — | **只可引用、不可打包**（现方案正是引用＋回退） |
| 微软雅黑 / 方正等商业字库 | 商业授权 | — | **红线：不打包、不内嵌**（此类诉讼多发） |

**对"开源项目不会被起诉"这条判断的校正**：

- **使用字体 = 复制 + 分发**，这两件事**与是否盈利无关**——许可证义务不因为"没赚钱"而消失；
  非商业授权也只在授权**明文允许**时才成立。
- 主要风险是**打包分发未获授权的商业字库**（把系统字体随包发出去是典型），
  以及**违反 OFL 的"保留名称"条款**（改字体后仍用原名）。
  近例：[霞鹜文楷作者 2026-06 的维权声明](https://www.appinn.com/lxgw-open-font-dispute/)，
  争点为第三方衍生字体沿用"霞鹜"保留名称——**开源权利人之间同样会发生此类诉讼**。
- 规则与第三方依赖一致：**采用前核实许可证，结论写进 `NOTICE`，
  随附许可证与版权声明，且不改名冒用。**

**当前方案：三层字体角色，均引用系统字体链 + 回退，暂不打包**（令牌 `fontFamily`；**替换机制见 §3.8**）：

| 角色 | 令牌 | 用在哪 | 为什么 |
|---|---|---|---|
| **界面** | `--font-sans` | 外壳、标签、列表、按钮、元信息 | 界面文字是**功能性**的，黑体类在 14px 下最清晰（**界面层不用宋 / 楷，判据见 §6.13；"不花"见 §3.9**） |
| **编辑** | `--font-mono` | 编辑区、代码、时间戳、表格 | 「一行即一段」的正文与代码混排时**对齐**是硬需求；中英 2:1 的等宽才不串行 |
| **阅读** | `--font-read` | 阅读 / 展示态（只读长文） | 只读时按"读"优化：行距更松、字距舒展；**将来可给衬线选项**（§3.8 允许用户换） |

**中文等宽字体是存在的**（作者此前存疑，此处确证），三条候选都可用：

| 候选 | 形态 | 许可证 | 备注 |
|---|---|---|---|
| **Source Han Mono / 思源等宽** | **真·中英等宽** | **SIL OFL 1.1**（[LICENSE 原文](https://raw.githubusercontent.com/adobe-fonts/source-han-sans/release/LICENSE.txt)，保留名称 `Source`） | Adobe × Google，**大厂维护、最稳**；与思源黑体同源 |
| **Sarasa Term SC / 更纱终端** | 中文等宽，**中英宽度完美 2:1** | **SIL OFL 1.1** | 社区口碑好；需要更强技术感字形时选用 |
| **Maple Mono CN** | 中文等宽，中英 2:1 | **SIL OFL 1.1** | 圆角风格；CJK 构建默认不产出，取独立发布物 |

**中文黑体（非等宽）候选**——若仅需比例字体（观感与易用优先）：

| 候选 | 许可证 | 可否**打包** | 可否**子集化** | 结论 |
|---|---|---|---|---|
| **Source Han Sans / Noto Sans CJK** | **SIL OFL 1.1** | ✅ | ✅（OFL 允许修改） | **首选**：无附加限制 |
| **MiSans**（小米） | 小米自有许可（[协议原文](https://hyperos.mi.com/font-download)） | ✅（"使用字体创作…应用 App，有权分发或出售该作品"） | ❌ **明文禁止"改编或二次开发"** | **可用但受限**：**不许子集化**，只能整字库随包 |
| **HarmonyOS Sans**（华为） | 华为自有许可 | ⚠️ **未核实**（官方页为脚本渲染，取不到条款原文） | ⚠️ 未核实 | **采用前必须取到许可证原文**，不凭印象 |
| 微软雅黑 / 宋体 / 楷体 | 随 OS 授权 | ❌ 不可打包 | ❌ | **只可引用名字、不可内置于包** |

> **注**：`--font-sans` 的字体链里**保留 `"Microsoft YaHei"` 只作回退**（Windows 上它总在），
> **不打包、不作为设计目标**；设计目标是 `system-ui` → 思源黑体系那一档。
>
> **"禁止改编"这条要点**：MiSans 与鸿蒙字体的自有许可都比 OFL 紧。
> **子集化（subsetting）属于"改编"**——文件被改过。故用 MiSans 就不能裁体，
> 而 CJK 整字库十几 MB 起，这直接决定包体。**需子集化时选用 OFL 的两条候选。**

**许可证合规（无论最终选谁）**：随附许可证与版权声明（`NOTICE` + 字体目录）、
**不得单独售卖字体**、**不得改名冒用保留名称**（如 `Source`）。
规则与第三方依赖一致：**采用前核实、结论入档、随附声明**。

### 3.8 字体替换机制（口径：不锁一套）

口径（2026-09-30）：**字体不锁一套——令牌即字体映射，用户可自行替换。**
默认给一套；**用户系统内已有的字体可自行选用**——
**这些字体由用户的系统提供，与本仓库无关，版权责任不在本仓库**。

**该推论的边界须写准，否则责任会回到本仓库**：

| 做法 | 谁在分发字体 | 版权责任 |
|---|---|---|
| **内置打包**：字体随安装包分发 | 本仓库 | **由本仓库承担**（须 OFL 那类明确允许打包的） |
| **引用系统字体**（只写字体名） | 操作系统 / 用户 | **不在本仓库**——这就是当前方案 |
| **枚举系统字体、列出名字**，由用户挑 | 仍是系统 | **不在本仓库**：只报告"装了什么"，不提供、不复制、不缓存 |
| 应用**代用户挑选并一键替换**成某商业字体 | 系统 | **不涉及**：应用代为选择即构成引导使用，责任回到本仓库 |

**故本机制的红线**：应用只提供**名字**与**替换动作**，**不代选、不复制字体文件**。

**三层，每层可单独覆盖**（角色见上文）：

```
--font-sans  界面   ← 默认：system-ui → 思源黑体系
--font-mono  编辑   ← 默认：Sarasa Mono SC / Cascadia / Consolas 链
--font-read  阅读   ← 默认：system-ui → 思源黑体系
```

**机制形态（与令牌机制一致，不加第二条链）**：令牌本就是 CSS 自定义属性，
故用户覆盖**就是在 `:root` 上覆盖这几个变量**——不新增构建环节、不做主题模块。

- **存储**：用户的选择存**应用级设置**（与卡片板布局同类；按记忆「前端设计」§三，不进库）。
- **生效范围**：全局（三层各一个值），不做"逐组件指定字体"。
- **应用方式**：`document.documentElement.style.setProperty("--font-mono", …)`。
- **默认与用户的关系**：沿用配置引擎的既有口径——**用户改过的值不被默认值覆盖**；
  默认只用于"未曾修改"的那一层。故升级更换默认字体时，已修改的取值不受影响。
- **连字（ligature）随默认字体一起给默认值**，归"字体包"约定。

**四处注意事项**：

1. **须判断字体是否存在**：写入不存在的字体名，系统会**静默回退**，
   界面呈现无变化而用户无从得知原因。故需一条"该字体在本机可用吗"的判定。
2. **枚举系统字体要经壳**：前端无此能力，须由壳提供。已核实到可用实现——
   [`tauri-plugin-system-fonts`](https://docs.rs/tauri-plugin-system-fonts/latest/tauri_plugin_system_fonts/)
   （**MIT**，`get_system_fonts() -> Vec<SystemFont>`）。
   **这属窗口与系统能力，不构成业务进入壳**（判据见 `.agents/skills/rules/references/ui-boundary.md` §一）。
3. **等宽由实测字符宽度判定，不看字形**：有些中文字体带拉丁等宽字形，但**中文字符不等宽**。
   "这字体适合当等宽"须由**实测字符宽度**决定（含中日韩字符），不能只看名字里有没有 `Mono`。
4. **替换后须有还原路径**：每个角色都要有**一个"还原默认"的动作**，否则用户改错后只能删除配置。

### 3.9 界面字体的"不花"判据（作者口径）

口径（2026-09-30）：**编辑面以外的字体不作等宽要求，观感优先；
装饰 / 花体族一律不进界面。**

这不是审美偏好：**花体的辨识特征来自笔形装饰，而装饰在 11–14px 的小字上会退化成噪点。**
更根本的理由与 §6.13 同族：**字形应匹配文字的功能**。

**故字体判据按"文字在界面里的角色"分三档**：

| 角色 | 例子 | 字体该做什么 |
|---|---|---|
| **底色** | 标签、列表、按钮、元信息、状态 | **最不抢眼**：中性黑体、字面率大、笔画均匀 |
| **主体** | 笔记正文、卡片标题 | 可有辨识特征，**但必须在 14px 下仍清晰** |
| **点缀** | 空态标题、展示态 | 可以有个性，**仍不许是装饰 / 花体族** |

> **一票否决（装饰 / 花体族）**：手写体、书法体、艺术字、带装饰笔画的"设计感"字体——
> 这些**只用于 Logo / 品牌素材**，不进界面。判据是"花不花"，不是"哪个厂商"。
>
> **与 §6.13 的分工**：§6.13 管"**层**"（界面层不用宋 / 楷这类**读**的字），
> 本节管"**花**"（装饰族一律不用），两条判据并行。**先过"层"，再过"花"。**

## 6. 布局契约（可拖 / 可收 / 聚焦）

> 状态：**意图**。Qt 时代曾按 QML 外壳实现，实现已随旧层删除；
> 下列行为是**产品口径**，前端落地时按此重建，实现文件引用已移除。

三栏结构：`活动栏（固定）| 导航 | 内容 | 属性`，相邻栏之间可拖拽分隔。

| 能力 | 规则 |
|---|---|
| **可拖** | 导航 / 属性栏宽度可拖；导航 168–480px，属性 220–460px，内容最小 360px |
| **可收** | 导航、属性栏可各自收起（隐藏即不参与布局）；活动栏在当前领域上再点一次＝收起/展开其导航 |
| **聚焦** | 收起活动栏 + 导航 + 属性，正文可读宽度由 720 放宽到 980；退出还原此前开合状态 |

- 控制入口就近：导航收起/展开在活动栏当前领域上再点一次（无需额外按钮）；
  「属性」开关进笔记页命令带。
- 快捷键：`Ctrl+B` 导航、`Ctrl+Shift+B` 属性、`Ctrl+Shift+Enter` 聚焦、`Esc` 退出聚焦。
- 正文列普通模式维持舒适行长（≤720），仅在聚焦 / 全屏时放宽；普通模式不按窗口全宽排布正文。
- 窗口边框一律交给系统（Tauri 的原生装饰即可）；**不再自绘标题栏与缩放命中区**
  （Qt 时代因 `FramelessWindowHint` 必须自补，前端形态下除非确需自定义标题栏，否则不做）。
- 悬停 / 选中高亮一律**即时**（不做颜色过渡），避免相邻项交叉淡入被看成"同时高亮两个"。
- 预留：栏宽可持久化。

### 6.1 笔记页命令带

标签栏下方一行动作（标签编辑在属性面板，不占命令带）：收藏 / 归档 / 复刻 / 关系 / 历史 / 分享 / 属性。

按钮统一为无边框幽灵样式；布局随文案变化重排（避免"已收藏"变长后覆盖相邻按钮）。

### 6.2 右键菜单

笔记列表项右键弹出菜单：打开 / 复刻 / 收藏 / 归档 / 分享… / 历史版本 / 关系图 / 移到回收站
（回收站内显示 恢复 / 彻底删除）。收藏、归档、回收站状态**（预留）**拟落在块的属性上
（`Attr` 声明的字段，如 `favorite` / `archived` / `trashed`）——那几个字段当前尚未声明，
领域载体在 `py_src/model/note/types/`，落点口径见[L0 存储设计](../storage-design.md) §3，
随领域层重建再定。

### 6.3 分享

分享是一等动作，独立弹层（不在属性区）：上半是**公开到个人主页**开关（语义上是开关，
不属于"分享给"）；下半**列出可分享的社区 / 成员**，点击即切换，不要求手输。
入口：命令带「分享」按钮、右键菜单「分享…」。

### 6.4 属性 = KV 检查器（默认收起）

面板默认**收起**，点「属性」按钮或标题栏箭头展开 / 收起。数据面输出 schema 驱动的 KV 列表
（`id / key / value / type / editable`）：文本只读浅色 / 可编辑深色、布尔开关。
当前字段：类型 / 库 / 作者（取笔记 `author`）/ 署名（`authors`）/ 签名（创作签名缩写）
**（预留：作者 / 署名 / 签名三项随 2026-09-29 的重建删除，随领域层重建再定）** /
标签 / 收藏 / 归档 / **可见性（私密 / 已分享 N 处）** / 创建 / 修改 / 字数 / 大小。
**标签为 KV 编辑**（`K : V` 两栏可编辑 + 添加/删除，无冒号则仅 K）。
关系以文字树（缩进 + ↖/↘）只读呈现。属性变化走独立通知，不触发正文重载动画。

> 预埋：标签存为 `K:V` 字符串，后续可据 `A:B`、`B:C` 推导 K 之间的父子关系，做「基于标签搜索」。

### 6.5 回收站

删除不逐次确认：右键「移到回收站」→ 进回收站（导航栏底部入口，带数量与「清空」）
→ 可恢复或彻底删除。

### 6.6 多选 / 批量

列表表头进入「选择模式」后逐项勾选，底部批量条**单行**四键：全选 / 收藏 / 回收 / 完成。

### 6.7 无障碍

把动效时长归零的「减少动效」开关，以及提升边界与文字对比的「高对比」开关；
入口在档案菜单「显示」。

### 6.8 关系图（竖排，类 Git 图）

左侧窄泳道（gutter）画连线与节点圆点，右侧整行卡片——线条与文字分区，互不遮挡。
泳道按「Git 式」分配（优先复用父节点泳道，分支开新道，合并回收），
节点按时间竖排（来源在上、派生在下），位置由拓扑算出，**不自由拖拽**。
卡片显示 角色（当前 / 来源 / 派生）+ 标题 + 作者 + 时间 + `复刻自 vN`。

> 前端落地时属复杂组件；采用现成图可视化库**之前先核实许可证**（§4）。

### 6.9 工具册

触发条在标题栏内；指针离开后按 `autoCloseMs`（默认 1500ms）延时回收；
点**面板外**任意处**立即**回收，点面板内（含空白）不回收。
工具册顶部输入框兼作**搜索 / 命令面板**：有输入时网格换成结果列表。

### 6.10 空态与新建

笔记导航**不放搜索框**：搜索 / 命令统一进**工具册**顶部输入框
（输入即筛、回车打开首条、无结果则以该文本新建、`Esc` 清空、关闭复位）。
列表空白处或编辑区空白处**双击**即新建空笔记。

### 6.11 悬停提示

全局单例提示组件：组件悬停调用显示接口，停留 550ms 后在指针附近显示；另有收起接口。
用于仅有图标的按钮（活动栏、导航图标、批量键、关闭 / 收起等）。

### 6.12 笔记列表（形态与分组）

导航笔记区渲染**分组树**（数据由领域给出，`group` 块）：

| 元素 | 行为 |
|---|---|
| 组行 | 折叠箭头 + 文件夹 / 锁 / 口令锁图标 + 名称（**双击改名**）+ 子项计数；悬停「＋」把**当前笔记**加进该组；**右键菜单**（加入当前笔记 / 只看此组 / 上移 / 下移 / 移出父组 / 设改清除密码 / 锁定解锁 / 删除） |
| 笔记行 | 点击打开、右键原菜单；多选勾选照旧 |
| 拖拽 | 笔记拖到组＝加入，拖到「未分组」＝移出全部组；组拖到组＝改挂父组（防环） |
| 口令 | 存 sha256 校验哈希（与身份摘要同源，见 `py_src/core/storage/db/id.py` 的 `digest`）；未解锁的组**不暴露子项**，点击弹口令框，解错重试 |
| 筛选 | 右键「只看此组」→ 顶部显示筛选条（可清除） |
| 无组时 | 不显示「未分组」头，直接平铺；有组时末尾附「未分组」 |

**显示形态**：在**详细**（标题 / 时间 / 一行摘要，62px）与**紧凑**（单行标题 / 时间，26px）
之间切换。组头「新建组」创建根组。成员关系两套都存（组内列表 + `contains` 关系）。

### 6.13 编辑器正文（行 = 段）

编辑器逐行渲染；一行即一段，字级样式走行内区间，段级属性走段元素
（见 `data-model.md` §5.1；**该页待重写，当前不在库**）。

- **软换行**：等效中文 ≤ 300 字时自动折行。
- **超长行**：> 300 字（阈值即 `OVERLONG_WEIGHT`，**常量待定**：代码中尚无此项）→ 不折行 + 该行可**横向滚动**
  （要求作者自行回车分段）；编辑区右下空白处出现**「到行末」按钮**，点击把光标移到行末并滚到最右。
  不自动拆、不弹提示。
- **段落属性**（对齐 / 标题 / 列表 / 缩进 / 引用 / 代码）随行渲染：标题调字号字重，
  列表**序号派生**，引用加左条，代码块等宽 + 底色 + 不折行。

> **前端落地提示**：本节的"一行即一段"与前端富文本的**块文档模型同构**，
> 是该模型选型的首要判据；选型时一并核实许可证。

**界面层不用宋 / 楷的判据（2026-09-30 补）**：问题不在字形本身，而在**摆放位置与文字功能不匹配**。
这不是审美问题，有三个具体原因：

1. **它们是"读"的字，不是"扫"的字**：宋 / 楷为**连续长文**设计，笔画细、粗细对比大、字面率低；
   界面文字是**扫读的短串**（标签、按钮、状态），在 11–14px 下渲染发虚。
2. **数字与拉丁字对不上**：界面里中英数混排（时间、计数、路径），宋 / 楷的拉丁部分只有一种选法，
   对不齐；等宽与黑体在这一项上天然占优。
3. **语体错位**：楷体自带"手写 / 文雅"的**叙事语体**。界面文字是**功能性**的，
   用楷体等于给功能文字配了叙事腔——**与 §3.5"不做过程动画"理由相同**：
   UI 不承载叙事，故不采用叙事形态的样式。

> **外推**：这条与 §3.3 的"当年只能这样"同族——**形与用不匹配，就是负分**。
> **允许的例外**：**阅读 / 展示态**（只读长文）按"读"优化，那里才可以考虑衬线或楷体，
> 于是有了 `--font-read` 这个角色；它**不用于界面**。

### 6.14 格式工具栏（两行）

标签页下方两行：**第一行字级、第二行段级**。布局由工具注册表驱动（数据），**位置不写死**，
将来可用户自定义。

- **工具注册表**：`Tool` 基类 + 参数化实例（如"加粗"开关、带对齐参数的段落工具…）；
  `group` 只作描述字段，**分组 / 位置是数据**，不进继承链。
- **按钮**：纯图标（少量文字字形 B/I/U/H1…）+ 悬停提示；点击即调用对应工具。
- **响应式**：一行放不下时右侧出现**展开箭头**，**向下抽屉**铺开全部工具。
- 标题栏最大化键：普通态单矩形、最大化态双叠矩形（随窗口状态切换）。
  **（2026-09-30 起）** 若采用系统原生窗口装饰，本项随之取消。
