# 配置引擎

> 状态：**现行**（2026-09-30 落地）。
> 事实源：`py_src/core/conf/`（引擎与 `conf` 面）＋ 各包自己的声明模块（`core/conf/params.py`、
> `core/storage/conf.py`）；本文件是**用法契约**，形状与注意事项同时写在代码的 docstring 里。

## 1. 一句话

**一个 `conf` 面、一种调用形、一份单文件投影**。声明与取值是同一个调用，差别只在给不给参数；
写只记一笔、退出时统一落盘；运行一次程序，值文件与词表即生成——**没有专门的生成脚本**。

```python
from core.conf import conf

conf("pack.max.byte", 2 * 1024**3, type=int, doc="封口线")  # 声明
ceiling = conf("pack.max.byte")  # 取值
```

**使用点统一**：import 之后任何位置都可直接调用，定位、缓存、补缺、落盘、词表这些机制细节
全部封装在 `conf` 内部。附带效果是**全仓只扫 `conf(` 这一个词**即可列出全部使用点——
声明与取值均为显式调用，「谁在使用配置」有确定答案。

## 2. 声明与取值：同一种调用

| 写法 | 含义 |
|---|---|
| `conf("a.b", 默认值, type=…, doc=…)` | **声明**（第一次写进值文件） |
| `conf("a.b", type=…, doc=…)` | 声明一个**没有默认值**的项（值必须由文件给，丢了报错） |
| `conf("a.b")` | **取值** |

参数：`path`（点分键）／`default`（默认值）／`type`（类型）／`doc`（写进词表，IDE 悬停可见）／
`file`（值放独立文件，见 §7）／`force`（强写，见 §4）。

**声明是唯一事实来源**：默认值只写在声明处，实现里不抄第二份（存储那组直接引用
`pack.DEFAULT_MAX_BYTES` 与 `slot.DEFAULT_SLOT_BYTES`，以保证一份事实、两处引用，
而非抄写一个数字）。

## 3. 事务：引擎自己组织，调用方不划批次

```python
conf("core.log.level", "WARNING")
conf("storage.pack.slot_bytes", 512)
```

写侧**只记一笔待写、立即返回**（写的耗时与读同一量级）；到该落盘的时刻才做完整一轮：
读旧值 → 补缺失键 → 一次写盘 → 词表重算一次。

**不提供 `with conf.scope()`**：批次边界由调用方手划会漏划（漏一次即退化为一次落盘）。
本层的写操作**幂等且无序**（只补缺失键、不改已写值），任意一批的子集、超集或重排后的落盘结果
均合法，**批次只是减少 IO 的优化，不是语义边界**；批次不承担语义，故不在接口上出现。

批内读取返回待写值：`conf(k, v)` 之后再 `conf(k)` 返回 `v`（引擎维护待写覆盖）；
返回旧值会使「写入后立即读取」的语义不成立。

## 4. 落盘的四条通路

| 通路 | 做什么 | 使用方 |
|---|---|---|
| **默认** | 只记一笔，进程退出时统一落盘（`atexit`） | 日常写法 |
| **`conf.sync()`** | 落盘全部待写项（值文件 ＋ 词表），并返回新增 / 改动的键 | 测试、工具、要求文件即时一致的场合 |
| **`force=True`** | 单键强写：**不进入待写批次**（立即落盘）＋ **允许覆盖已有值** | 显式改值 |
| **退出保底** | 同上第一条，进程正常结束时执行 | 无需调用 |

`sync()` 落盘全部待写项，`force=True` 使单键不进入待写批次；两条通路共用同一段落盘代码。

**注意事项**（影响有限，集中记在此处）：

- **默认不即时**：崩溃时丢失的是尚未落盘的那几笔写入。这不是数据损坏——声明固定在代码里，
  已落盘的值不受影响，重启即可恢复；**值文件只可能比预期旧一个版本，不含错误内容**。
  丢失的仅限「文件里没有、代码里也未声明的键」，该类键本就没有可读值。
- **只读环境下写盘失败不报错**：值文件是投影，写不出去不影响本次运行；读值不依赖写成功。
- **值文件缺失 / 陈旧不是错误**：缺失按声明重建，陈旧只补缺失的键。
- **词表不因声明加载不全而清空**：只 import 了部分模块的进程，写出的词表仍是完整对象，
  不会写成空对象。

## 5. 写入方向单向：代码 → 文件

```python
conf("core.log.level", "WARNING")  # 声明（第一次）
conf("core.log.level", "DEBUG")  # 报错：该键已有值
conf("core.log.level", "DEBUG", force=True)  # 强写：允许覆盖
```

**写入任务只有两种**——建立无数值的项、建立带默认值的项；其余调用均为**读取**。
**改值只能从配置文件改回**（值文件是改值的入口），除非显式 `force=True`。

该约束产生两项结果：

1. **重复声明在启动时即报错**，报错发生在**声明的调用点**（既非两次静默覆盖，也非延迟到落盘
   才报），并带上先声明处的出处（文件名 + 行号），用于定位冲突的两处声明；
2. **使用者修改的值受保护**——代码持有的默认值不覆盖文件中的改动，覆盖必须显式写
   `force=True`，责任明确。

判据是「**本会话已声明过**」，而非「文件里存在该键」：否则删除值文件中的键再重新写入
会与该判据冲突。使用者自加的键（登记表未记录的）**始终保留**——引擎只补缺失键，
不删除也不修改非本次声明的键。「曾声明、后已删除」的键在下一轮落盘时消失
（既不在登记表内，也不属于使用者自加）。

## 6. 类型：由形参给，声明期就校验

```python
conf("storage.pack.slot_bytes", 512, type=int, doc="槽长")
conf("ui.zoom", 1.0, type=float)
```

- **判等用 `type(v) is T`，不用 `isinstance`**——`isinstance(True, int)` 为真，但 `bool` 与 `int`
  在 JSON 中是两种类型，`type=int` 配 `True` 必须拒绝；
- **唯一放宽的是 `int` 值配 `float` 类型**（无损提升），且放宽后**按浮点算**：
  默认值 `512` 会落成 `512.0`，否则读回的值是整数、与 `float` 判据不符（该校验会拒绝它）；
- 反向（`type=int` 配 `1.5`）一律报错，值为整数值的浮点同样不通过；
- **类型必须落在 JSON 能表示的那几种里**：`int` / `float` / `bool` / `str` / `list` / `dict`，
  可带一层元素（`list[int]` / `dict[str, int]`），外加 `None`。`bytes` / `datetime` / `Path` /
  枚举 / 元组 / 集合在声明期即拒绝；该限制是类型判据可执行的前提；
- **读写两侧同一套判据**：人工改坏的文件同样在声明处即报错，不静默按另一个类型使用；
- 省略 `type=` 时按默认值自身的类型判。

静态类型：声明处返回绑定的 `TypeVar`（所以 `x: int = conf("a.b", 1)` 与
`conf("a.b", 1).bit_length()` 都成立、默认值给错类型也能被静态抓到）；取值处没有注解即 `Any`。
**边界**：静态检查发现不了键名字符串写错，也不做「键 → 类型」的全局推导。

## 7. 文件引用：值放独立文件

`file="yaml"` 让这一项的值放进独立文件，默认**同层级的 `<字段名>.<类型>`**：

```python
conf("some.key", "", type=str, file="yaml")  # 值文件里那一行是 "some.yaml"
```

引用名由声明处计算（不取默认值），且**不得越出配置根**；被引用的文件必须已存在——
缺失在**声明期即报错**，不延迟到读取时。值文件中的该行是**实际引用**：改为其他相对引用
即指向另一个文件。

**该能力存在，内核当前无使用它的键**：它曾经被表声明用过（`config/tables.yaml`），
而表声明这条链**已经整条取消**——表的形状由 `ID` 的字段现算（`ID_FIELDS`），
不再读也不写任何声明文件（见[存储设计](../storage-design.md) §8.1、§12）。
故这一节描述的是**仍在实现里的一项能力**，只是当前没有调用方。

## 8. 投影：两份产物，跑一遍就生成

```
config/settings.json          ← 值（使用者可改；顶部 $schema 指向词表）
config/schema/settings.json   ← 词表（给 IDE 悬停与分发看的 JSON Schema）
```

- **键逐字保留点分形式**（`"pack.max.byte"` 是一个属性名，不展开成嵌套对象）：
  `conf("…")` 里那个字符串是全仓唯一的检索词，代码与文件逐字一致，`grep` 才能无遗漏地检索；
- **没有生成脚本**：两份产物由引擎在落盘时写出，运行一次程序（或 `pytest`）即一并生成。
  入库的产物与声明是否分叉，由 `tests/core/test_conf_projection.py` 检查；
- 词表带 `type` / `description` / `default` / `x-cairn-owner`（声明它的模块）/ `x-cairn-site`
  （声明处的文件与行号）；`docs/reference/config.md` 由 `scripts/docgen.py` 从**声明现算**渲染，
  不读入库的那份副本。

## 9. 边界

- **声明归属各自**：使用方在自己的包里声明（存储参数在 `core/storage/conf.py`，内核自己的在
  `core/conf/params.py`）；配置端只负责展开与取值，不替其他包管理；
- **格式常量不进配置**：载体魔数、文件头长度、记录头布局这类改了会坏库的，留在实现处
  （`core/storage/pack.py` 的 `MAGIC` / `HEADER_SIZE` / `RECORD_HEAD_SIZE`）；
- **已落盘的东西不被新配置改写**：格长写进载体文件头，此后按文件头读；
- **引擎不依赖第三方**：只用标准库＋`core.exc`；
- **环境旋钮 `CAIRN_CONFIG` 不是配置项**：它是**定位配置根的手段**（测试与部署重定向），
  值文件里不会出现它。

## 10. 未做（如实记）

- **「流写」/ 定时窗口落盘暂不做**：它在「进程退出」之外再添一处「何时落盘」，而要求
  「文件即时一致」的场合已有 `force=True` 与 `sync()`。**重启条件**：出现「长驻进程且外部读者
  要持续看到较新文件」的需求再论；
- **不做「值来自声明还是使用者改过」的来源标记**：只按「文件里有没有这个键」判，故使用者把值
  改回默认值后，该键的「已改动」状态不再保留；现有需求不要求记录来源；
- **值投影仍是单文件**（十万行以内不分片）：拆分需先有量级依据；
- **手写口 / 多来源合并**（个人覆写、部署覆盖）未做。
