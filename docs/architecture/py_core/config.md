# 配置引擎

> 状态：**现行**（2026-10-04 换 OnConf；2026-10-07 随 OnConf 2.0 收口）。
> 事实源：`py_src/core/conf.py`（**装配**：定配置根 ＋ 关控制台日志出口）、各包自己的声明
> 模块（`core/params.py`、`core/storage/conf.py`）、以及**上游库** OnConf
> （PyPI 名 `onconf`，Apache-2.0）。本文件是**用法契约**；引擎自身的语义以上游文档为准，
> 此处只记"内核侧怎么接的、边界在哪"。

## 1. 一句话

**内核不自带配置引擎，也不在引擎前面包一层转发**。`core/conf.py` 只做引擎的**装配**：
定配置根（`CAIRN_CONFIG` 指的目录，不给就用仓根下的 `config/`），并把控制台日志出口关掉。
声明与取值一律用 OnConf 自己的 `conf`：

```python
from onconf import conf

conf("pack.max.byte", 2 * 1024**3, doc="封口线")  # 声明
ceiling = int(conf("pack.max.byte"))  # 取值
```

**装配必须早于第一次 `conf()`**：OnConf 的引擎是单例，引导层参数（`home` / `file_name` /
`log_console` 一类）起来之后不可改，而内核的声明发生在**导入期**。故 `core/__init__.py`
先导入 `core.conf`、再导入声明模块：**导入 `core` 即完成装配**。仓内要声明配置就按这个顺序
（声明模块都在 `core` 之下，导入它必先跑 `core/__init__.py`）。顺序弄反时，装配那一句会因
"引擎已经启动"当场抛 `ConfError`，不会静默落到错误的配置根上。

## 2. 声明与取值：同一个调用，两种模式

| 写法 | 含义 |
|---|---|
| `conf("a.b", 默认值, doc=…)` | **声明**（文件里没有就补上；文件里已有则尊重文件） |
| `conf("a.b", doc=…)` | 登记一个**没有默认值**的项 ⇒ 紧接着取值，没配即报错 |
| `conf("a.b")` | **取值** |

参数面只有 `key` / `value` / `doc` 三样（2.0 起封闭）：`value` 给没给就是"写还是读"的判据
（`None` / `0` / `""` 都算给），`doc` 写进词表，供 IDE 悬停与参考页使用。

- **声明是唯一事实来源**：默认值只写在声明处，实现里不抄第二份（存储那组直接引用
  `pack.DEFAULT_MAX_BYTES` 与 `hub.DEFAULT_SLOT_BYTES`，一份事实、两处引用）；
- **键逐字保留点分形式**，值文件里 `"pack.max.byte"` 就是一个属性名，不展开成嵌套对象。

## 3. 落盘：每次声明即提交，运行期不删键

| 通路 | 做什么 | 使用方 |
|---|---|---|
| **默认** | 每次 `conf(k, v)` 当场提交（引擎的 `flush_window=0`） | 日常写法 |
| **进程退出** | OnConf 自己 `sync()` 一次，兜底 | 无需调用 |

引擎的 `sync()` / `flush()` 仍在，但**内核侧不包它**：`flush_window=0` 之下没有待提交的
声明，"完整提交点"退化成空动作（`scripts/docgen.py` 原先那次调用即属此类，已删）。

**运行期不删键**：删除的判据"事实有、期望没有"只在**期望集完整**时成立，而运行期的期望集
只是本进程声明过的那部分。故 `conf()` 的任何出口都不删键，值文件里没声明过的键**原样留着**；
收敛（删多余键、覆盖既存值）由命令行 `onconf build` / `sync` 做。

## 4. 写入方向：代码 → 文件，单向且不覆盖

```python
conf("core.log.level", "WARNING")  # 声明；文件里没有就补上
conf("core.log.level", "DEBUG")  # 文件里已有值 ⇒ 尊重文件，只记一条 skip
```

**改值走配置文件**（人编辑是改值的正路）。运行期**没有覆盖出口**：2.0 取消了 1.0 的
`force=True`，覆盖属于命令行的人工动作。

## 5. 类型：不记、不推断、不转换

2.0 起 `type=` 整体取消，词表只记**键 / 说明 / 默认值**：

- **不推断**：值的类型由载体决定，引擎对值透明——文件里写 `"8080"`，读回来就是字符串；
- **不转换**：要整数在取用处写 `int(conf("…"))`，存储那组包装函数（`slot_bytes` 一类）正是
  这么收口的；
- **不校验**：`config/schema/settings.json` 是键 / 说明 / 默认值的投影（给 IDE 悬停与分发），
  不是类型约束。

## 6. 配置根与产物

```
config/
  settings.json          ← 值（使用者可改；顶部 $schema 指向词表）
  schema/settings.json   ← 词表（给 IDE 悬停与分发看的 JSON Schema）
  audit.log              ← 引擎的审计日志（运行期簿记，不入库）
  theme/…  shapes.json   ← 与配置引擎无关的**手写**声明文件，只是同住一个目录
```

- **配置根有一个旋钮 `CAIRN_CONFIG`**：只给测试与部署重定向，**不是配置项**（它是"找到配置的
  办法"），值文件里不会出现它。引擎自己的根旋钮是 `ONCONF_HOME`、缺省 `./conf`；本仓显式给
  `home`，因为缺省落点与仓里 `config/` 的位置不同；
- **审计日志不落终端**：引擎的日志是一个记录、两个出口——文件那个没有开关（缺省
  `<root>/audit.log`），控制台那个由 `log_console` 开关。内核是被命令行与测试嵌入的一方，
  一次导入要读十几条键，故内核把控制台**关掉**，`audit.log` 留全量记录；
- **写权限由进程树定**：创建引擎的进程是属主，派生进程只读（引擎记下创建时的 pid，另看
  `ONCONF_OWNER_PID`）。**注意**：属主进程会把这个变量写进 `os.environ`，它 spawn 的 Python
  子进程会继承，于是子进程被判成派生进程、写配置即抛 `ConfError`。要让子进程自己当属主
  （它确实是全新进程），就在它的环境里摘掉这一项；
- **值文件是单份**：文件名主干 `settings` 与类型 `json` 都是引擎缺省值，本仓不改。

## 7. 无生成脚本，但入库

两份产物**没有专门的生成脚本**：跑一遍程序就顺带生成（每次声明当场提交）。入库与否由
`tests/core/test_conf_projection.py` 拦——它拿**一个空目录里新生成的那一份**当基准比对入库的
那一份，故"声明改了、产物忘了重生成"会被它抓住。

参考页 `docs/reference/config.md` 由 `scripts/docgen.py` 生成：键 / 默认值 / 说明读入库词表，
**声明处**由 AST 扫 `conf(...)` 调用点得出（只认字面量键；写在循环里的键显示 `—`）。

> 词表格式在 2.0 变了（不再写 `type`），但引擎**不会因为格式旧就重写词表**：写盘只由对账
> 动作触发（键缺失，或说明 / 默认值与声明不一致），声明集与登记项都没动时一个字节都不写，
> 旧格式会一直留在盘上。故升级那一次要**删掉词表再生成一次**，让 `to_schema` 写出新形态。
> （词表顶部的 `x-onconf-hash` 在 2.0 只被写入，不参与"写不写"的判断。）

## 8. 语义变化（按版本逐条记住）

| 事项 | 1.0 | 2.0（现行） |
|---|---|---|
| **未声明过的键** | 提交点被清掉 | **运行期原样留着**，收敛归命令行 |
| **覆盖既存值** | `force=True` 逐键强写 | **没有这个能力**，走命令行 |
| **类型** | 声明期校验默认值 | **取消**：不记 / 不推断 / 不转换 |
| **引擎参数** | 可经 `conf(**engine)` 透传，含 `log=` | **只走 `AutoConf`**，参数面封闭；日志拆成文件与**控制台**两个出口 |
| **跨进程** | `.lock` / `.key` 握手文件 | **属主进程**（pid ＋ `ONCONF_OWNER_PID`） |
| **外部手改的可见性** | 等下一次提交才进内存 | 读之前比指纹（`mtime` ＋ 大小），改过就重读 |
| **异常** | `KeyNotRegisteredError` / `KeyHasNoValueError` / `TypeConflictError` / `ConfError` | 同左，`TypeConflictError` 随类型校验一起取消 |
| **重复声明同一键** | 静默放行（只更新词表） | 同左 |

> **未知键不再被清**是 2.0 与 1.0 最直观的反转：1.0 的口径是"键空间由声明定，不由文件定"，
> 2.0 把删除移出运行期——多进程下运行期的期望集永远不完整。

## 9. 边界

- **声明归属各自**：使用方在自己包里声明（存储参数在 `core/storage/conf.py`，内核自己的在
  `core/params.py`）；`core/conf.py` 只管装配，不替其他包管理；
- **格式常量不进配置**：载体魔数、文件头长度、槽头布局这类改了会坏库的，留在实现处
  （`core/storage/pack.py` 的 `MAGIC` / `HEADER_SIZE` / `RECORD_HEAD_SIZE`）；
- **已落盘的东西不被新配置改写**：格长写进载体文件头，此后按文件头读；
- **引擎不是本仓的代码**：配置语义归 OnConf；内核侧只保留"配置根 ＋ 日志出口"两件事。

## 10. 未做 / 已知限制（如实记）

- **OnConf 没法静态类型化**：2.0 的 wheel 里仍没有 `py.typed`，故 `pyproject.toml` 给
  `onconf` 那一组开了 `ignore_missing_imports`。上游补上之后删掉那段；
- **"重复声明即炸"这条看门能力没有**：要它得另找地方做（例如一道扫描 `conf(...)` 调用点的
  AST 门禁）；
- **不做"值来自声明还是被改过"的来源标记**；值文件仍是单份。
