## 0. 概述

**输入一个领域对象，UI 内核自动生成一棵可用的界面结构（初稿），开发者仅补细节；
数据变更经内核事件（`py_src/core/event/` 的 `Event`，由 `Bus` 扇出）单向通知至界面。**

目标四项：

1. **数据直通**：编写 UI 时不需了解数据内核的内部实现，按常规方式使用即可。
2. **快捷创建**：新增对象或界面的成本应与规模相称，先自动生成、再行调整。
3. **事件绑定**：由内核统一提供，声明式绑定并编译，不手工连接信号。
4. **统一 Config**：主题样式与 UI 配置集中于一套文件，语义轻于 CSS。

## 1. 定位与边界

- UI 内核是 **材质之上的应用框架**，非控件库；机制由内核提供，页面与外壳由 app 组合。
- **技术路线（2026-09-30 起）：Tauri 壳 + Web 前端**（React / TypeScript + Vite），
  Python 内核以边车形态在壳之外运行。Rust 只负责窗口与系统能力，业务逻辑不进入壳。
  旧的「Widgets 宿主 + QML 岛」及其判据（Qt 只支持 Widgets 里嵌 Quick 等）**已随 Qt 作废**。
- **领域专向**：领域集合已知（note / project / canvas / asset / group），按需特化，
  不追求通用到难以维护的抽象。
- **各司其职（Web 式前后端分工）**：领域对象除结构与事件外，还对外声明 UI 可消费的
  **契约**（字段 / 动作 / 信号）；UI 据契约绑定与生成。**契约属领域，渲染属 UI**，互不越界。
- **总目标（唯一尺度）**：以更便捷、更快、更轻量、更少工作量完成 UI 开发；
  与之冲突的机制不予采纳。
- **单向数据流**：内核 → 投影 → 视图；视图 → 意图 → 命令 → 内核。
  **不引入响应式框架、依赖追踪或 diff / reconciler。**

## 2. 分层与依赖方向

```
app        页面 / 外壳（只写组合）
   │
ui.kernel  UI 内核：对象生成 · 描述编译 · 投影 · 绑定 · 配置
   ├─ facet      交付单元：对象 → UI 定义（生成 + 绑定）
   ├─ projection 对象 → 视图模型（纯数据，无材质）
   ├─ bridge     内核事件 → 前端可消费的通知
   ├─ binding    意图 / 命令表
   └─ config     Theme（封闭）+ UiConf（开放）
   │
材质层  Tauri 壳（Rust：窗口 · 系统能力 · 边车管理）+ Web 前端（React / TS）
   │
core / feature   数据内核（Qt-free）
```

> 材质层怎么摆本文不管——这是 `.agents/skills/rules/references/ui-boundary.md` 的事。
> 本文只主张一件事：**内核与材质之间隔着 UI 内核这一层**，故换材质不动内核。
> **（2026-09-30 起）** 通信形态与壳的分工已定（记忆的「界面」§二）；
> **契约的类型同步方式未定**（同篇 §三），未定之前本节不作为编码依据。

**约束（以 import 依赖固化，非仅文档约定）**：

```
ui  →  core.types（中立 DTO / 身份凭证） + 领域契约
ui  ✗  core.storage（Block / 桶 / 载体）
ui  ✗  feature
ui  ✗  存储内部（body / attrs / checksum / 载体 / 索引库 …）
```

- **Bucket / Block 为存储实现，与 UI 无耦合**：UI 不导入、不复用、不感知。二者职责正交——
  前者负责字节存储、去重与版本化，后者负责对象的呈现、能力与变更通知。
- UI 代码不得出现 `bucket` / `block` / `body` / `attrs` / `checksum` / `type=notedata` 等存储词汇。
- **边界判据**：若理解 UI 需先掌握 Bucket / Block，则边界已失效。
  UI 的心智模型应为：**领域对象 → 契约 → 界面**。
- 数据内核**不导入任何界面框架**（含 Qt 与前端运行时）；领域对象不认识界面。
- 增设架构测试，断言 `ui` 不导入 `core.storage` / `feature`。

> 与旧规则「UI 不 import feature / 不碰 Vault」同向；此处将边界固化为：
> UI 仅消费**中立类型 + 领域契约 + 投影**，写回仅经**命令**。

> 原记目录（`src/core/signal/`、`src/ui/core/`）已随 2026-09-29 的重建删除；
> 信号层与 UI 内核目录**尚未重建**。

## 3. 支柱一：数据直通

### 3.1 信号代理：内核可变更，UI 保持稳定

- 内核随业务与数据持续变更，UI 需保持稳定；**中介为代理**。UI 仅对代理编程，
  内核变更由代理适配，UI 不随之改动。**代理即稳定面。**
- **两端各设代理**：
  - **数据侧**：原设计为 `core.signal.Signal` 封装内核（领域体系）——该层已随 2026-09-29
    的重建删除，现行事件面为 `py_src/core/event/` 的 `Event` / `Bus`（见 [`kernel.md`](./kernel.md) §2）。
    代理作为**稳定面**与**取实体操作入口**的定位保留，具体形态待重定；
    它**不生成页面**——页面生成属 `Facet`。
  - **UI 侧（2026-09-30 起）**：原为"Qt 信号槽封装为同构代理"，前端落地后改为
    **前端可消费的通知与意图**（具体形态待定，见 `ui-boundary.md` §六）；两者同属"稳定面"，
    只是接口换了语言。**这条待重写。**
- **绑定（`Bind`）连接两个稳定面**；绑定对象因此是必要构件，而非可选装饰。
- 变更流向（2026-09-30 起）：`内核 → 数据侧代理 → Session（投影缓存）→ UI 侧代理 / Bridge → 前端状态 → 组件`。

#### 3.1.1 事件层与语义信号（`core/signal` 已删除）

> **（2026-09-30 起）** 本节原以 `core/signal` 与 `core/events.py` 的 `EventBus` 为底座，
> 两者已随 2026-09-29 的重建删除。现行事件层是 `py_src/core/event/` 的 `Event` 与 `Bus`
> （投递语义与事件目录见 [`kernel.md`](./kernel.md) §2）；语义信号层**尚未实现**，下表与下列条目属设计意图。

底座为现行事件总线 `Bus`（`py_src/core/event/bus.py`），其投递语义适用：
**提交后通知、按注册顺序投递、异常隔离、失败清单交回**。在其上分两层：

| 层 | 内容 | 示例 |
|---|---|---|
| **存储事件（已实现）** | 块级事实（事件目录常量 `object.put` / `object.deleted`） | 块写入 / 删除 |
| **语义信号（未实现，预留）** | 各域声明的语义通知（事件类型句柄） | project 的 `members_changed` |

四项动作：**声明**（本域发出与关注的信号）、**发出**（`emit(event)`）、
**订阅**（`subscribe(类型, 处理)`）、**投递**（沿用总线语义）。

- **域间不导入，仅识别信号**：note 不依赖 project，但可订阅其成员变更。
- **订阅方不缓存假设**，收到信号后重新读取当前状态；由此消解外部域状态突变的耦合风险。
- **发出方不等结果**（通知而非命令）；处理器内不得触发写入（事件在落盘后发出）。
- 域对外的**信号 / 动作句柄**（见 §3.3 的 `signals`）形态待定。
- **信号命名 = 域 + 变更**：挂载于公共总线，须避免冲突；字符串标识用短名 `<域>.<变更>`
  （如 `project.members_changed`），不使用裸名 `changed`；并在契约中**登记**（供查询与 UI 校验）。
- **数据形态由领域定义**，不存在 UI 与领域之间的额外格式；唯一要求为普通领域数据
  （非 `Block` 等存储对象），且须声明，订阅方方能知晓。
- 原 `src/core/signal/` 目录已随 2026-09-29 的重建删除（**未重建**）。

### 3.2 投影（Projection）

- 对象**不直接置入界面框架的模型**；先投影为**类型化视图模型**（row / DTO），再行渲染。
- 投影按需缓存；变更通知到达时按 `oid` 失效重算。
- 写回一律经**命令**（见支柱三），不直接修改对象。

### 3.3 领域契约（各司其职）

领域对象除结构与事件外，还须对外声明 UI 可消费的契约（Web 式前后端分工）：

| 契约项 | 内容 | 提供方 |
|---|---|---|
| **fields** | 字段集合、类型与显示提示（标签 / 分组 / 可编辑性 / 控件） | 领域声明，中立投影 |
| **actions** | 支持的语义动作（收藏 / 归档 / 复刻 / 删除 …）、参数与可用性 | 领域声明 |
| **signals** | 变更通知（存储事件 + 本域语义信号） | 内核 + 领域 |

- **契约属领域，渲染属 UI**：领域仅声明"具备什么"，UI 决定"呈现为何"。
  领域**不指定控件、不接触界面框架、不涉及像素**。
- **契约不得依附于 `Block`**：字段描述符（`Attr` / `Data`）属存储机制，**不外泄至 UI**；
  在内核边界内投影为中立 `FieldSpec{名字, 种类, traits}`，UI 仅读 `FieldSpec`。
  派生在边界内完成，UI 不可见其来源。
- **字段由领域对象分析得出，不写死**：UI 分析领域以获得字段与类型；领域新增字段时 UI 随动
  （**信号**告知当前字段集）。
- **显示属性为可选槽位**：`label`（显示名）/ `group`（分组）/ `display`（控件；缺省按类型映射）/
  `editable`（只读 / 可编辑 / 隐藏）。取值由领域提供，可由类型推断者省略；并非写死字段，
  而是可选提示。
- 无契约的领域亦可降级显示（退化为裸对象）；契约是**加性**的，逐步补齐。
- UI 按契约名称机械绑定 / 生成，**无需检索领域代码或猜测**。

### 3.4 直通的前提（数据内核配合）

使「新增字段即自动呈现」成立，数据内核须补齐：

| 事项 | 现状 | 目的 |
|---|---|---|
| **字段内省（中立投影）** | 缺（字段声明仅在类型登记内消费，见 `py_src/core/storage/format/block.py`） | 边界内产出 `FieldSpec`，不外泄 `Attr` / `Data` / `Block` |
| **字段显示提示（纯数据）** | 缺 | 显示语义随契约声明，不导入界面框架 |
| **语义信号层** | 缺（现行事件层 `py_src/core/event/` 仅块级事件，见 [`kernel.md`](./kernel.md) §2） | 域间语义通信 + UI 代理同源 |
| **facade 收口** | 已结（2026-09-29）：`Vault` 已解散，现行短面为 `Kernel` 的 `store` / `load` / `drop` / `locate`（[`kernel.md`](./kernel.md) §1） | UI 只见稳定接口 |

## 4. 支柱二：快捷创建（对象驱动生成）

本节为核心，也是与逐界面手写的根本区别所在。

```
领域契约 (fields / actions / signals)
        │  ① 读取契约（经中立投影）
        ▼
   UI 结构（自动生成，可用的初稿）
        │  ② 套用通用架构 + 补默认行为
        ▼
   开发者仅修改细节（增 / 删 / 换）
```

> **交付单元 = `Facet`**：一个域的整套 UI 定义；`__init__` 仅做两件事——**属性配置与绑定**。
>
> - **自包含**：主题等内置属性由 `Facet` 自带。
> - **不自包含**：布局与部件须自行导入、选择、配置后置入；其**专属配置属于自身**
>   （先修改得到新对象，再 `set` / `add`）。
> - **`set` = 设定形态**（"是什么"）：`layout.set(Grid)`。
> - **`add` = 登记所持**（"装了什么"）：`layout.add((1, 2), Editor)`。**两者语义不可混淆。**
> - **产物**：编译所得即**对象本身**（`Facet` 或其包装对象，完整描述结构与样式），
>   直接交由 App；App 加载并挂载，流程结束。**不序列化、不引入中间格式。**
>   定义为被动方，编译 / 挂载由外部发起。
> - `Page` 作为**内层页面层**保留。

### 4.1 自动生成的产物

1. **默认行为（必然项）**：应用已具备**通用大架构**（标题栏 / 活动栏 / 导航 / 内容 / 检查器 …）。
   对象接入后自动挂载：页面形态、保存与版本检查点、选中、搜索索引、事件订阅、生命周期。
2. **结构初稿**：按对象类型给出默认页面形态（列表 / 详情 / 画布）；
   字段按**类型映射表**给出默认控件（`str→单行输入`、`bool→开关`、`dict→KV 编辑器`、
   `list[oid]→引用列表`、`Canvas→画布组件` …）。**（2026-09-30 起）** 具体条目待前端落地时重定，
   "控件"一词在前端语境下即"组件"。
3. **细节（工作量本身）**：布局微调、专用控件、交互细节——系统无从推断者不予臆测。
   自动生成始终仅为**初稿**，不虚标已实现。

### 4.2 原则

- **特化优于通用**：领域已知，按需特化，不做过度抽象。
- **生成的仍走同一套编译**（见 §4.3）：初稿即结构树，修改初稿即修改结构节点，
  再一次性编译为界面结构（**2026-09-30 起**：不再是"Qt 树"，而是前端组件树）。
- **加字段 ≈ 仅在领域声明一处；加控件 ≈ 仅在原子目录增加一处。**
- **验收指标**：新增领域字段 = 领域一处（+ 显示提示），UI **0~1 处**；新增标准动作 = 契约一处，
  通用 UI 自动呈现。**若新增字段仍需修改 5 个 UI 文件，则设计失败，应回头修订契约。**

### 4.3 描述编译（生成与手写的共同底座）

- 结构 → 界面树，**单向编译一次**；扩展仅新增 translator（注册表），`Raw` 为一等逃逸通道。
- **不引入 reconciler 或响应式**：响应仍经数据侧代理 → Session → 模型。
- 结构词汇分两类：**布局组织器**（纯几何：Box / Grid / Split / Stack）与
  **组件 / 页面**（原子 + 组合 + 页面）；增长仅限原子与页面，外壳稳定。
- **画布 / 大关系图这类复杂组件按普通原子处理（2026-09-30 起）**：原为"QML 岛"，即"特定领域的增强组件"；
  前端落地后它们就是**普通的第三方前端组件**（画布 / 图可视化库），
  对外只暴露"配置入 / 事件出"，接法与普通组件一致（`bind.add(组件.事件, 域信号)`）。
  **选型时先核实许可证**（画布与可视化库多为 AGPL，见 `rules/references/licensing.md` 红线）。

> 与已废弃的 `decl` 的关系：问题域相同，取舍继承（单向编译、translator、Raw、不造响应式）；
> 实现另行立项。旧记录见 `.agents/skills/memory/references/decisions/`。

### 4.4 多页面（`Facet` 内的 `Page`）

单域通常不止一页（note：列表 / 编辑 / 关系 / 历史）。故在 `Facet` 内引入 `Page` 层：

- **`Page` = 单个页面**：一组布局 + 部件 + 绑定，是导航目标。
- **`Facet` 持多个 `Page`，并声明切换方式**（`tabs` / `stack` / 主从），默认 `tabs`。
- **单页域无需显式声明页**：`Facet` 自身即默认页，可直接 `self.layout.set(...)`。
- 宿主（页签 + 堆叠）由 **App 提供**；页面**首次显示时才构建**（懒加载），
  切换触发 `on_enter` / `on_leave`。

> **（2026-09-30 起）Qt 实现已作废**：下列 Python 示例为 Qt 时代的描述形态，
> 落地机制待按 Tauri + Web 前端重写（**预留**）；`Page` 分层与懒加载的主张保留。

```python
class NoteFacet(Facet):
    def __init__(self):
        super().__init__("note")  # 领域用 kind 字符串；默认页直接配置
        self.layout.set(Table)
        self.add((0, 0), Title)

        edit = self.add_page("edit", title="编辑")  # 追加页面
        edit.layout.set(Grid)
        edit.add((0, 0), Editor)

        self.navigate(mode="tabs")  # 声明切换方式
```

## 5. 支柱三：事件绑定

### 5.1 事件来源（材质侧机制，作者无需接触）

> **（2026-09-30 起）本节待重写**：与 Qt 无关的那部分（"作者只面对统一信号，不接触底层事件对象"）
> 继续有效；下面三条是按 Qt 具体写的，前端落地后按同样的三层结构改述。

- **物理层**：鼠标 / 键盘 → 材质框架的原生事件对象 → 组件的底层事件钩子。
- **组件层**：材质框架的组件把常用物理事件提炼为**原语事件**（点击 / 输入 / 提交 …）；
  原生写法是组件之间直接绑定处理器。
- **统一化**：UI 侧代理把「物理事件」与「组件事件」**统一封装为界面信号**；
  自定义组件或手势才需自行从底层事件提炼。
  作者**只面对统一信号，不接触材质框架的事件对象**。

### 5.2 `Facet.__init__` 仅声明两件事

`Facet` 是**一个域的整套 UI 定义**（布局 + 部件 + 绑定）；`__init__` 内仅声明：

1. **属性配置**（修改属性）
2. **绑定**（仅声明，不在此时建立连接）

> **（2026-09-30 起）Qt 实现已作废**：下列 Python 示例为 Qt 时代的描述形态，
> 落地机制待按 Tauri + Web 前端重写（**预留**）；"仅声明、不建立连接"的主张保留。

```python
class NoteFacet(Facet):
    def __init__(self):
        super().__init__("note")  # 认领域（kind 字符串）；self.note = self.domain()

        # ① 属性配置
        self.layout.set(Grid, rows=4, cols=4)
        self.add((0, 0), Title)
        self.add((1, 2), Editor)

        # ② 绑定（声明）
        bind = Bind(self)
        bind.add(self.save_btn.clicked, self.note.favorite)  # UI 信号 → 领域动作
        bind.add(self.clear_btn.clicked, self.on_clear)  # UI 信号 → 本类方法
```

- `self.save_btn` 是**描述节点**，非活动控件；`.clicked` 是其声明的信号。
- `self.note = Signal(Note)` 由 `Facet` 基类持有（一个域一个代理）。
- 真正的连接在**编译 / 挂载**阶段由 `Bind` 建立。

### 5.3 `Bind` 模型

> **（2026-09-30 起）Qt 实现已作废**：本节词汇按 Qt 控件信号写成，
> 落地机制待按 Tauri + Web 前端重写（**预留**）；绑定为声明 + 编译、单向、非响应式的主张保留。

- `Bind(self)`：绑定登记处，**作用域 = 该 `Facet`**，随生命周期自动释放。
- `bind.add(source: Signal, target)`：
  - **source** 为 UI 侧信号，**明确到信号**（`self.save_btn.clicked`），不做隐式主事件。
  - **target** 可为**领域 `Signal`**（`self.note.favorite`）或**本类方法**（`self.on_clear`）——
    UI→内核 与 UI→UI 采用同一种写法。
  - **参数沿 source → target 传递**；签名不匹配或信号名不存在，**编译期报错**。
- 两端词汇固定（控件信号表 + 领域契约信号表），故校验可在编译期完成。
- **绑定是声明 + 编译**；**非双向绑定，亦非响应式运行时**。
- **事件与转换分离**：信号**携带数据**；UI 收到后**可用则直接使用，需转换则以自身方法转换**
  ——转换为 UI 自身职责，非内核规定。
- **单一通路**：一个数据变化仅一条通知路径；一个用户动作仅一条命令路径。

## 6. 支柱四：统一 Config

**格式：JSON。** 分两层，职责明确：

| 层 | 词表 | 职责 | 真源 |
|---|---|---|---|
| **Theme** | **封闭** | 外观：色 / 圆角 / 间距 / 字号 / 字体 / 动效 / 阴影 | 外观唯一真源，组件仅引用 `token.*`，禁硬编码 |
| **UiConf** | **开放** | 组件 / 页面的行为与配置，随组件生长 | 支持新增 / 覆盖 / 重定向 / 失效 |

> 外观令牌的词表、取值与落地机制的事实源是 [`ui-theme.md`](./ui-theme.md) §2–§3；本节只定分层与职责。

- **顶层 `token {…}`** 统管全局外观（颜色等）；其余为**具体配置**：`note.<…> = 值` / `note.<…> {…}`。
- **App 自动生成 JSON schema**：App 认识所有 `Facet`，据此可得域 / 部件 / 布局 / 属性集合，
  合法配置键**自动列出**（IDE 可校验 / 补全），编写便捷。
- 部件与布局的属性皆在此呈现，**含布局参数**——布局可自由拖动，参数落入本文件；
  **用户可在不改代码的前提下调整界面**。
- 重叠处用 **「属性设状态、样式选状态」** 的伪状态桥缝合。
- 加载即校验（schema），未知段 / 键**报错**，不静默失效。
- 应用级设置（最近打开、键位、界面状态）**独立存放，不进 bucket**（非领域偏好）。

## 7. 与数据内核的关系

- **方向**：数据内核为底座（Qt-free、传输无关）；UI 内核只读经投影、只写经命令。
- **正交**：UI 内核不感知存储实现（Bucket / Block / pack / catalog / 内容池一律不可见）。
- **协作点**：领域契约（fields / actions / signals，经中立 `FieldSpec` 投影）、信号总线（通知）、
  命令（读写）。

---

## 8. 不变量（红线）

1. **UI 仅消费中立类型 + 领域契约 + 投影**：**不导入 `feature`，亦不导入 `core.storage`
   （Bucket / Block）**；数据内核不导入任何界面框架。
2. **契约不得依附于 `Block`**；UI 代码不得出现 `bucket` / `block` / `body` / `attrs` /
   `checksum` / `type=notedata` 等存储词汇。
3. **单向数据流**：内核 → 投影 → 视图；视图 → 意图 → 命令 → 内核。
4. **不引入响应式框架 / reconciler**；绑定为单向编译。
5. **不改 `Block` 顶层字段**；UI 不感知存储结构。
6. **自动生成仅产出初稿**；未实现的细节不虚标（不可用项显式禁用 / 不展示）。
7. **外观仅来自 Theme**；组件内禁硬编码颜色 / 间距 / 圆角。
8. **`set` 与 `add` 语义不可混淆**（设定形态 / 登记所持）。
