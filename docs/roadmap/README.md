# 路线图结构说明

> 本页是 `docs/roadmap/` 下各份路线图的**格式与维护口径**。路线图文件只装数据
> （路线增量 + 版本分配），怎么读、怎么写、怎么改都在这份里。
>
> 路线图在权威顺序里居首：**`路线图 > 设计 > 代码`**（口径见[架构索引](../architecture/index.md) §权威顺序）。

- **范围**：每份路线图只管一条版本线（`1.x.md` 管 1.x）。下一条线另开一份（`2.x.md`）——
  按版本序列切分才不会庞大无比；每条线到它为止，此后只维护未落定版本，不再增量。
- **只记开发路线，不记修复路线**：缺陷修复、补丁类 issue 一律不上路线图。条目只由**主动加入**的
  能力与决策构成，不是"做过多少"的流水账；版本号也不会因修复而虚涨。
- **上下两块**：`## 路线增量` 收全部条目（唯一事实源），`## 版本分配` 按版本关联条目 ID。
- **路线增量**是增量性质的：新决策随时加上去，完成就打勾。条目按归属层层嵌套（层 → 模块 → 条目）。
- **路线ID**：三位序号（`001`、`002`…），**全局唯一、顺序发号、号不复用**；条目改名不改号。
  号在全部路线图文件里**连号**（`2.x.md` 接 `1.x.md` 的最大号往下），故 `grep 001` 不会撞上第二份。
- **条目卡片**：每个条目固定六行，缺项留空不删——字段是栏位，不是正文。
  - `决策状态`：`已定` / `待裁` / `未定` / `未来项` / `已废弃`；破折号后接该状态的具体所指。
  - `设计关联文件`：设计口径在哪一页。`docs/` 内用相对链接；仓内其他位置用反引号路径，
    其中 `decisions/…` 指 `.agents/skills/memory/references/decisions/`，`rules/…` 指 `.agents/skills/rules/references/`。
  - `分配实现版本`：落在哪个具体版本——`1.0.0` / `1.0.1` / `1.1.0` / `1.0.0-alpha.N`；未定写 `待定`，废弃写 `已废弃`。
  - `具体实现文件`：代码落在哪；尚未建就写明缺哪一层，不写「无」。
  - `关联 issues / PR`：GitHub 编号；`未合` 标注尚未合并的 PR。
- **勾选框**：`- [x]` 表示这条**不在待办里**——收口了，或是废弃了；两种情形靠括号分辨。
  - **收口**：条目名后不加注。
  - **废弃**：曾经定过、现已不再做，且**既无代码也无设计**的条目——**不删**，打勾并在条目名后注 `（已废弃）`。
    留痕是为后人不再重新提一遍。
- **版本分配**：每个版本号下列该版本关联的条目 ID。版本只有两种状态：
  - **已发布**：标题后注 `（已发布）`——写死，此后不再变动。
  - **未落定路线**：标题后注 `（未落定路线）`，或什么都不写（默认即是）。分配仍可调整——
    改分配是**纯增量**（条目只增不减、版本号只增不减），不视为推翻。
  废弃条目汇总在 `### 已废弃`，不占版本号。
- **条目模板**：新增条目照抄下面六行，字段顺序不变。

```text
> 路线ID:
> 决策状态:
> 设计关联文件:
> 分配实现版本:
> 具体实现文件:
> 关联 issues / PR:
```
