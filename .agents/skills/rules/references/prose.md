# 书面语规则（文档一律非口语化）

## 标准

**凡落进仓库的文字，一律非口语化**：文档、代码注释、docstring、commit message、
Issue / PR 描述、规则与记忆。日常讨论不限；**产品交付物不保留聊天语气**。

理由：文档的读者是"三个月后的自己"与"不认识作者的开发者"。口语化会把
**当时的情境**（和谁讨论、为什么兴奋）一起带进去，而那部分对读者是噪声；
同时它让人分不清哪句是**规定**、哪句是**当时的想法**。

## 三类文体的基准

| 文体 | 在哪 | 基准 |
|---|---|---|
| **规格 / 契约** | `docs/architecture/*.md` | 定义式陈述；`必须` / `不得` / `仅` / `即`；编号小节；不做劝说 |
| **操作说明** | `docs/guides/*.md`、`README.md`、`docs/contributing/*.md` | 步骤、命令、判据；一句一事；不复述设计理由 |
| **工作备忘** | `.agents/skills/memory/` + `rules/` | 紧凑条目；`已定 / 待定 / 已废弃` + 理由；不写心情与过程 |

三者都不使用：第二人称、语气词、比喻、感叹号、表情、网络用语。

## 用词对照

**词典本体在 `scripts/prose.py` 的 `_LEXICON`（唯一事实来源）；本节只给判据与改写方向，
不重复列出禁用词**——否则本节自身会被检查器命中（本文件受同一门禁约束）。

改写方向，按类别：

| 类别 | 判据 | 改写为 |
|---|---|---|
| 第二人称 | 出现第二人称代词 | 本仓库 / 作者 / 使用者 / 开发者 |
| 第一人称口语 | 出现口语化的第一人称复数 | 本仓库 |
| 语气填充词 | 起停顿、软化作用，删掉不影响语义 | 删除；确需承接用「事实上」 |
| 口语副词 | 表随意或顺带完成 | 一并 |
| 口语时间副词 | 表「以后再说」 | 待补 / 尚未实现 |
| 口语化的问题描述 | 用生活化说法指代技术故障 | 已遇问题 / 注意事项 |
| 口语化的完成义 | 用俚语表示完成 | 完成 / 无法完成 |
| 口语祈使 | 用劝阻语气写规则 | 改为「不得」陈述句 |
| 拟人化比喻 | 把文档、记忆、进程写成有意志的主体 | 换成事实描述 |
| 非正式标点与网络用语 | 波浪号、重复感叹号、数字梗 | 不用 |

**比喻一律不写。** 具体禁用词不在此复述（本节自身受同一门禁约束）；
判据是：把文档、记忆、进程、工作流写成有意志的主体，即为比喻。
改写方向一律是**事实描述**——对象是什么、发生了什么、后果是什么。

## 怎么查（不靠自觉）

```powershell
uv run python scripts/prose.py            # 全仓检查；有命中即非零退出
uv run python scripts/prose.py docs src   # 只查指定目录
uv run python scripts/prose.py --list     # 打印词典
```

- 工具是**词表驱动**的确定性检查：`scripts/prose.py` 的 `_LEXICON` 就是标准本体。
  发现新的口语词**加进词典**，不要在文档里绕开它。
- 扫描面：`.md` 全文 + `.py` 的 docstring 与注释（字符串字面量不查——那是给用户的界面文案）。
- 排除面：生成物（`docs/api/`、`site/`）、第三方（`.agents/skills/skill-creator/`、
  `git-commit/`）、评审记录（`docs/review/`）、博客（`docs/blog/`）。
- 加词典时只收**歧义为零**的词；有歧义的（如 `搞` 单独出现）改写成精确正则再收，
  宁少收不误报。

## 写作要求

1. **陈述事实，不做劝说**：写「本目录不引入 GPL 依赖」，不写劝阻语气的同义句。
2. **一句一事**，长句拆开；不使用「如前所述」「众所周知」这类过渡填充。
3. **不写过程**：文档记录结论与理由，不记录推理过程的反复。
   过程属 `memory/changes.md`，且只留一句。
4. **不写元话**：文档不讨论自身。生成声明只在页面顶部留一行，其余删除。
5. **加粗只用于定义与判据**，不用于强调情绪；一篇文档的加粗处应能直接当提纲读。
6. **术语按 `docs/reference/glossary.md`**；同义词不得混用。
