# Cairn 项目记忆

**这个技能本身就是项目的记忆**（可变、活文件）。内容只有两类：

| 类别 | 位置 | 说明 |
|---|---|---|
| **决策** | [`references/decisions/`](references/decisions/) | **一个主题一个文件，只写现状态**；文件顶部列出全部主题 |
| **进度 / TODO** | [`progress.md`](progress.md) | 独立文件，**只记"还没做 + 在做"** |

## 怎么读

- 任务开始时，只读与当前任务**相关的**那一两个文件，不必全读。
- 记忆只是现状快照；与代码或 `docs/architecture/*.md` 冲突时，**服从事实**。

## 怎么写（格式）

每条标明**状态**（`已定` / `未定` / `待裁` / `未来项`）与**理由**：

```
- 已定 · <约束>：<为什么这么定>。
```

每个决策文件**末尾带一节「变更记录」**，一行一条：

```
- <日期> · <改了什么> | 为什么：… | 否掉了什么：… | 后果：… | Git：<hash>
```

**那是索引，不是过程**——细节看 `git show <hash>`，不在这里复述。

## 硬规矩（写之前先读这一节）

1. **决策文件只写现状态**。同一主题**只有一个文件**：新决定来了就**改写同一份**，
   不新建 `<主题>-2.md`，不在文件里按日期堆版本。
   **一件事有多份"旧版本"，就是逼读者自己比对——那等于没有文档。**
2. **不记"哪天改了什么"**。按日期的流水账与 `git log` 重复，且必然过期；
   `git log` 有 diff、有作者、有日期，比手写的记录更准。
   **要留的是索引（变更记录那一节），不是过程。**
3. **理由只留"为什么否掉"与"为什么只能这样"**。前者防止别人重新提一个已被否掉的做法；
   后者防止实现走回头路。判断标准：**这些话在代码与 `git log` 里找不到**，才值得写。
4. **不复述代码与设计文档**。已落在 `docs/architecture/*.md` 或 docstring 里的事实，
   记忆里不再重复——重复必然分叉。
5. **没有归档**。过期、被更大变化取代、与事实不符的条目**直接删**；
   **不留"历史文档"让人比对新旧两份**——归档留着与不留没有区别，只增加阅读成本。
6. **进度文件只记"还没做"**。做完的条目**删掉**，不改成 `[x]` 留在原地当历史。
7. **每条都要能过期**：写下时就该能判断"什么情况下它不再成立"，否则它迟早变成垃圾。

## 清理机制（硬性）

- 每次任务收尾**一并清理**：过期、已废弃、与代码或文档不符的条目 → **删除或改写**。
- 记忆必须比代码更短、更新更快；**只增不减会腐化失真**。
- 与 `docs/architecture/*.md` 冲突时以事实为准，记忆服从事实。
