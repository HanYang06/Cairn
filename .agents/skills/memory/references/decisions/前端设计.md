### 一、设计原则（其余各条都由它推出来）

- 已定 · **张力 = 留白 + 决策**，不是配色、不是炫技。两条可判定的口径：
  **留白＝谁在负责这块空**（答不上来是谁在管的空，就是空洞）；
  **决策＝把选择成本摆在谁头上**（按钮位置由"用户此刻的站位"决定，不按"动作属于哪个对象"归类）。
  细则：`by-design.md` §1、§3。
- 已定 · **界面的骨架是有限集，外壳不发明新原型**：只从既有原型里选，
  力气全花在"留白与决策"这套参数上。**原型分容器与导航两组**，两者可叠加、不可混谈。
  一眼判据：并列两件以上 → 看位置谁定 → 使用者定且坐标带语义是**画布**、
  只是习惯则是**卡片工作台**、开发者定死则是**分区式工作台**。
  细则：`by-design.md` §7。
- 已定 · **单动作原则**：**UI 不是越复杂越好、颜色不是越多越好；清晰、简单、单一动作就够**，
  **UI 动作越多越丑**。落成三条：**一屏一个主操作**（能用右键菜单的就不搬到界面上）；
  **不做过程动画**（切换即切换、不加中间过程——连贯动画需要叙事支撑，而 UI 承载不了叙事）；
  **交互反馈时长上限 180ms**，悬停与选中一律即时。
  **唯一豁免**：启动画面与进度反馈（那是状态，不是叙事）。细则：`ui-theme.md` §3.5。
- 已定 · **「当年只能这样」的视觉习惯，技术成熟后不改即是负分**：扁平与硬棱角当年成立，
  是因为渲染能力只能那样；技术代价消失后继续保留，会被读成"没做"或"复古"。
  **可外推**到硬边框、纯色块、无状态过渡。理由（作者口径）：**当时确实没这个技术**。

### 二、页面结构：卡片工作台

- 已定 · **容器 = 卡片工作台**（原为"待裁"，骨架已落地并合并，故转现行）。
  **它与分区式工作台是两种容器，不是同一原型的两档**——
  **分区式的布局单元由开发者定（固定分区）；卡片式的布局单元由使用者定（卡片）**。
  故卡片式里**没有"导航栏 / 检查器"这类固定位**，只有一张张卡，位置与大小都是**数据**。
  **卡片是唯一单元**：笔记 / 待办 / 速记 / 集合 / 关系都是卡片，差别只在类型与内容。
  板内保留视图切换（卡片 / 流 / 看板 / 专注），即「同一空间换态」。
  **否掉**：把卡片工作台并进**画布**——画布的坐标参与内容语义，卡片板的坐标只是人的习惯。
  细则：`by-design.md` §4、§7。
- 已定 · **舞台只有「卡片」一种单元**；项目 / 组 / 标签是**镜头（过滤器）**，不是顶级分区。
  "进项目" = 换镜头，不是换世界。
- 已定 · **卡片四粒度**：卡 → 展开（卡内编辑）→ 专注（占满）→ **落板（拿空间坐标）**；
  规则视图是派生，画板是手动覆盖。
- 已定 · **根布局三带**：顶带（工具栏，相对固定）+ 舞台（主区）+ 任务栏（长期任务）；
  边缘（导航 / 检查器 / 关系 / 版本）按需出现、默认收起；专注时全隐。
- 已定 · **捕捉与整理 = 同一空间换态**（不另开捕捉窗）：浏览（卡片流）/ 专注（一卡占满）/
  组织（看板 / 画板）——换态不换窗。
- 已定 · **两种密度**（只留两种）：卡片（大 / 中图标）/ 详细（列表）；混排靠 `kind` 颜色区分。
- 已定 · **顶带 = 工具栏**：搜索 / 命令常驻，其余功能走**伸缩抽屉**。

### 三、布局机制（尺寸语义）

- 已定 · **尺寸 = 整数格 + 拖动吸附**：卡片位置与大小一律为整数格 `(x, y, w, h)`，
  **不存像素坐标、不存小数比例**；指针拖动只给"原始比例"，由它决定"拖到哪儿算一格"
  （吸附半径），**落盘一律就近取整**。参照安卓主屏的图标缩放，
  但把"预设小 / 中 / 大"换成**可拖比例**——自由与可存因此兼得。
  **否掉**像素自由摆放（必然碎化、无法自动重排）。细则：`by-design.md` §8。
- 已定 · **四条防碎化硬约束**（自由摆放的经典死法是对不齐、空洞、越拖越乱）：
  **吸附**（只在整数格落位）· **最小 1×1** · **自动补位**（卡缩小或移走后后方的卡补上）·
  **禁止重叠**（同一格只属一张卡，放不下就顺延）。
  **不是可选项**——它们坏了不会报错，只会让板子慢慢碎掉，故由用例守
  （`app/tests/layout.test.ts`）。
- 已定 · **卡片组：组本身仍是一张卡**（有 `(x,y,w,h)`，可移可缩放），递归由此成立；
  组内按同一套网格算。**嵌套深度待裁**（一层够用且好实现；不限层带来命中测试与渲染成本）。
- 已定 · **布局是用户数据**：卡片的位次与大小由使用者产出，**不进库**（应用级设置独立存放），
  也**不塞进 `conf()`**——配置引擎的口径是"声明在代码里、改值从文件来"
  （`config.md` §5），硬塞进去等于每次拖拽走一次 `force=True` 覆盖写入。
  布局另走自己的文件与自己的读写；**只有布局机制自身的旋钮**（网格列数、最小尺寸）才是配置项。
  坏掉的布局**不报错**：它是视图偏好，不是数据源，读不动就回默认板。
- 已定 · **键盘与指针同等可达**：方向键移动、`Shift` + 方向键改尺寸；
  每个角色都要有"还原默认"的出路。

### 四、色与主题

- 已定 · **浅色优先，深色可选**：默认主题是**亮色**，深色跟随系统、可手动覆盖。
  理由（作者口径）：**产品的底色要跟产品做的事走**——Cairn 是管项目、写笔记，
  阅读与书写的总时长压倒一切；深色当默认的是终端与代码编辑器那一类。
  **浅色纸面不取纯白**，用 `#F7F5F2`（亮度比纯白低约 8.5%，减眩光又不到"显黄"），
  由此形成纸面 → 面板 → 浮层三级明度。
  **否掉**：纯白纸面（长时间阅读眩光更重）；也**不删深色**——低光环境下它仍然对。
- 已定 · **品牌色：冷石不动、强调改暖金**（按 logo 取色重定，不是凭感觉）。
  从 `assets/logo/png/cairn-256.png` 逐像素取色：**石头本身是冷的**
  （暗部 `#0E1319` R−B ≈ −11、受光 `#3A434C` ≈ −18），故深色底 `#0D1117` **不改**；
  唯一错位的是强调色原先用了冷蓝。改为 logo 里那道暖金——
  **深色 `#EDB761`（对 `#0D1117` 对比度 10.41）/ 浅色 `#8A5F22`（对纸面 5.16）**，均过 AA。
  **冷暖相对**，暖金自然成为画面里唯一的光源。细则：`ui-theme.md` §3.1。
  **否掉**：把底色改成暖黑（与 logo 不符，且会毁掉"冷底 + 一点暖光"的对比）；
  浅色主题直接用 logo 原金（对白底仅 1.82，不可用）。
- 已定 · **对比度是机器守的**：`app/tests/tokens.test.ts` 断言
  "浅色底不是纯白"与"两套的正文 / 强调色对各自背景都过 AA"——**加色即过门禁**。
  三级文字（正文 / 次要 / 弱）形成层级，**不靠加边框**；边界刻意弱，
  辨识靠留白与明度分层。

### 五、字

- 已定 · **字号阶梯**（参照 VS Code 的克制：**阶距不狠但可辨**）：
  `11 / 12 / 14 / 17 / 20 / 26 / 36`。关键一处是**界面正文 14px 而不是 13**——
  13 与 12 站得太近，读起来"平均"。细则：`ui-theme.md` §3.2。
- 已定 · **三层字体角色**（三种需求，不是一套字体的三个版本）：
  **界面**（扫读的字：标签 / 列表 / 按钮）· **编辑**（要对齐：正文与代码混排、时间戳）·
  **阅读**（顺读的长文，只读态）。
- 已定 · **界面层不用宋 / 楷**（作者命意：**问题不在楷体本身丑不丑，而在摆放的位置不对**）。
  三条具体原因：① 它们是"**读**"的字不是"**扫**"的字（笔画细、字面率低，11–14px 下发虚）；
  ② 与拉丁数字**对不齐**（界面里中英数混排）；③ **语体错位**——楷体自带叙事腔，
  而界面文字是功能性的（与"不做过程动画"同一条道理）。
  **允许的例外**：阅读 / 展示态按"读"优化，那里才可以考虑衬线。
- 已定 · **花字一票否决：不进界面**（作者口径"用花字就是命"）。
  **判据不是"哪个厂商"，是"花不花"**——手写体、书法体、艺术字、带装饰笔画的"设计感"字体
  只用于 Logo / 品牌素材。理由：**花体的性格来自笔形装饰，而装饰在 11–14px 的小字上
  退化成噪点**。字体判据按"文字在界面里的角色"分三档：**底色**（最不抢眼）/
  **主体**（14px 下仍清晰）/ **点缀**（可有个性，仍不许装饰族）。
  **与"不用宋 / 楷"是两把尺子**：先过"层"，再过"花"。
- 已定 · **中文等宽字体确实存在，三条候选皆 OFL 1.1**（核实过许可证原文）：
  **思源等宽 Source Han Mono**（真·中英等宽，Adobe × Google，最稳）·
  **Sarasa Term SC**（中英宽度完美 2:1）· **Maple Mono CN**（圆角风格）。
  中文黑体首选 **思源黑体**（OFL，**可子集化**）。
- 已定 · **字体不锁一套：三层各可替换，且默认不打包**。
  覆盖写在**独立的一层**（`--font-<角色>-user`），样式读
  `var(--font-sans-user, var(--font-sans))`——**兜底仍是令牌，字体名只有一处真源**。
  **红线**：应用**只给名字与替换动作，绝不代选、绝不复制字体文件**
  ——"代用户一键换成某商业字体"等于应用在引导使用，责任会回来。
  **校正一条误判**：使用字体＝复制＋分发，**义务与是否盈利无关**，
  "开源项目不会被起诉"不成立（近例：[霞鹜文楷 2026-06 维权声明](https://www.appinn.com/lxgw-open-font-dispute/)）。
  **当前方案**：引用系统字体链 + 回退、**不打包**；将来要打包中文等宽，
  **体积与子集化必须一起定**。细则：`ui-theme.md` §3.7、§3.8、§3.9。

### 六、零件与冻结项

- 已定 · **动作可以胶囊，容器不做胶囊**：主操作一屏**最多一个**（实心胶囊），
  次级一律幽灵胶囊；列表行、菜单项、卡片、输入框**全是矩形**。
  代价是行高变高、同屏能放的动作变少——**这正是想要的**。
- 已定 · **阴影与圆角已冻结，今后尽可能不要变**：二者管**全体组件**的共性观感，
  **稳定比"稍微更好一点"值钱**。口径：**不夸大、不放任，但必须看得出来、感觉得到柔**
  ——阴影要**两层**（小偏移勾边缘 + 大模糊给柔感，单层做不到）；圆角要**随尺寸走**
  （够不够柔不只看数值，还看与元素尺寸的比例），**外层半径 ≥ 内层半径**。
  **冻结机制**：① 档位**只增不改**；② 要改必须带**功能性证据**（对比度不达标之类，
  视觉偏好不算）；③ **试验值不许进 `config/theme/tokens.json`**。
  细则：`ui-theme.md` §3.3。
- 已定 · **生成规则与工艺**：**不写 CSS 的结构性保证**——样式绑进组件、上层只做编排；
  页面里的间距只许用布局原语与令牌档位。**联动在控制器，不在控件之间**（零件只发意图，
  禁止控件互连）；**布局靠原语嵌套组合，不新增原语**；**组合可递归，深度不设限**；
  **增长只在原子与页面**。
