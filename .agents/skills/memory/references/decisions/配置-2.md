## 配置（2026-09-29 重定 + 已定形；**2026-09-30 已落地**）

> 已落地（`src/core/conf/`、`core/storage/conf.py`、`tests/core/test_conf*.py`；用法契约见
> `docs/architecture/config.md`，落地记录见 `references/changes/2026-09-30.md`）。本文记形状与理由。
> 作者口径：**越简单越好**——简单到可以在任何地方无孔不入地用起来，扫起来也只要找一个词。

- 已定 · **没有生成配置的脚本**（2026-09-30 作者定，原打算留一个 `--check` 工具）：跑一遍程序
  就顺带生成——引擎本就在退出时落盘，为它单开一个脚本是把同一段逻辑写第二遍。
  连带三件事：① 旧的 `tools/gen_conf.py` **删除**；② 防漂移改由
  `tests/core/test_conf_projection.py` 承担（跑一遍即生成，入库产物与声明不许分叉，
  另含一个子进程用例验证"退出即生成"）；③ `tools/docgen.py` 的参考页改成**从声明现算**渲染，
  不再读入库的那份副本（它要的是事实，不是副本）。

- 已定 · **声明与取值同形**：只有一个 `conf` 面、只有一种调用形状，差别只在给不给参数。
  `from core.conf import conf` 之后任何地方都能用——这就是"无孔不入"的全部含义
  （不是"在所有地方挂号"）。声明侧带默认值，取值侧不带：

  ```python
  conf("storage.pack.slot_bytes", 65536, doc="槽长：载体内的定长分配与定位单位")  # 声明
  slot = conf("storage.pack.slot_bytes")                                        # 取值
  ```

  理由：不设 `get` / `set` / `Cfg(...)` 第二套动词，少一层体感；且**全仓只扫 `conf(` 这个词**
  就能列出全部使用点（声明与取值都不隐身），"谁在用配置"这个问题有确定答案。
- 已定 · **事务由引擎自己组织，调用方不划批次**（2026-09-29 作者定；推翻了先前的 `with conf.scope()`）：
  直接连写即可，引擎在底层把它们合成一次处理。

  ```python
  conf("core.log.level", "INFO")
  conf("storage.pack.slot_bytes", 65536)
  ```

  理由：局部看是"小事务"，整体看调用密度很高——批次边界由调用方手划既不自然，也会漏
  （漏一次就退化成一次落盘）。故**不提供 `scope`**：没有批次栈、没有嵌套语义。
  引擎侧的样子：`conf(key, value)` **只记下待写、立即返回**（所以写和读一样快），
  到"该落盘的时刻"一次性做完整轮——读旧值 → 补缺失键 → 规范键序 → 一次写盘 → 词表重算一次。
- 已定 · **批内读得到待写值**：同一进程内 `conf(k, v)` 之后再 `conf(k)` 必须取到 `v`
  （引擎维护一层待写覆盖），否则"写了立刻读"会读回旧值，用法就自相矛盾了。
- 已定 · **落盘时机 = 进程退出（`atexit`）为保底 + 显式 `conf.sync()` 当逃生口；不做时间窗口兜底**
  （2026-09-29 作者定）：退出落盘晚到无所谓，因为**配置不是即时数据**——它不从网络来、
  不需要先到先得，只要求"该有的有"。故丢待写不算数据事故，顶多算一次重启即可恢复的可用性问题。
  作者的三条判据：① 值写死在代码里（声明处），丢了下次照声明重展开；
  ② **该落的本来就落着、不该落的本来就不存在**；③ **该读的本就在文件里、不该读的本来就读不到**。
  严格说，用户手改的值进程读过即进内存、崩溃也不伤文件，所以连手改都不会丢。
  唯一"真正丢掉"的情形是：文件里没有、代码里也没声明的键——那本来就不算数（见"无孔不入"那条）。
- 已定 · **`sync()` 是维护入口，不是日常用法**：工程工具（`--check` 之类）与测试要"文件此刻是对的"
  时显式调一次；日常写法里不出现它（它只强制落盘，不划批次）。
- 已定 · **落盘有四条通路，分工写明**（2026-09-29 作者补 `force`）：
  ① **默认 = 只记一笔**（同上一节：调用即返回，退出时统一落盘），日常写法走这条；
  ② **`sync()` = 整批刷掉**，给工具与测试"文件此刻是对的"；
  ③ **`conf(k, v, force=True)` = 强写**（作者 2026-09-29 定）：它同时放开两件事——
     **不许攒着**（立即落盘）与**允许覆盖已有值**（见下条"写入方向"）。
     语义是"这一笔就是要改、谁也拦不住"；整批刷掉是 `sync()` 的活，`force` 只管这一笔。
     与 `sync()` 的区别：`sync()` 是"把攒着的都刷掉"，`force` 是"不要把它攒着"。
     实现上 `force` 只需"写进去 + 立刻 sync"，故两条通路共用同一段落盘代码。
     给写侧用，读无此参数——**读没有"立刻落盘"可言**。
  ④ **退出时统一落盘**（保底）。
  `force=True` 时**写失败必须报出来**（这是显式请求），不像退出那条通路只能记日志吞掉。
- 已定 · **写入方向只有一个：代码 → 文件；改值属例外，须显式 `force=True`**（2026-09-29 作者定）：

  ```python
  conf("core.log.level", "INFO")                 # 声明（第一次）
  conf("core.log.level", "DEBUG")                # 报错：已经有值了，代码不许再赋值
  conf("core.log.level", "DEBUG", force=True)    # 强写：就改
  ```

  作者的口径：**写入任务只有两种**——`conf(k)` 建无数值的项、`conf(k, default)` 建有默认值的项；
  其余只能是**读取**。**改值只从配置文件改回来**（人编辑文件是改值的正路），除非显式开强写。
  这条一举拿到两样：① **重复声明在启动时就炸**（不是两次静默覆盖，也不是等到落盘才炸）——
  报错发生在**调用点当时**，并带上先声明那一处的出处（`inspect` 取文件名与行号），
  免得只知道"撞了"却不知道撞的是谁；② **用户手改的值天然受保护**——
  代码手里的默认值不会把文件里的改动顶掉，想顶必须自己写 `force=True`，责任明确。
  判据里的"已经有值"= **本会话已经声明过**（含同一批里的待写项），**不是"文件里有这个键"**——
  后者会把"删掉值文件里的键再补回来"这条常态堵死（落地时实测踩到，故判据按会话算）。
  用户自己加的键（登记表没见过的）永远留着；"曾声明、后已删除"的键随下一轮落盘消失。
  默认值只写在声明处这条不变——**声明一次即止，改值不是声明**。
  `force=True` 是唯一能顶掉文件里值的通路，故它的 docstring 要写明这是覆盖。
- 已定 · **静态类型：用 `TypeVar` 绑定，不引插件、不生成 stub**（2026-09-29 作者定"类型留着"）：
  声明处返回绑定的 `T`（所以 `x: int = conf("a.b", 1)` 与 `conf("a.b", 1).bit_length()` 都成立、
  默认值给错类型也能被静态抓到）；取值处没有注解即 `Any`，有了注解即按注解算。
  **边界如实记**：静态检查抓不到"字符串键写错"（键本质是字符串），也不做"键 → 类型"的全局推导。
  将来要更强（生成 stub 之类）再议，暂不为它买单。
- 已定 · **不做"值来自声明还是用户改过"的来源标记**：当前口径只按"文件里有没有这个键"判，
  故用户把值改回默认值后，这一笔的"改过"记录就丢了。现有需求不要求记住来路，暂不记。
- 已定 · **落地时定下的三处细节**（2026-09-30，都不影响上面的形状）：
  ① **值投影落 `config/settings.json`**、词表落 `config/schema/settings.json`（值文件顶部
  `$schema` 写相对引用 `schema/settings.json`）；**点分键不展开成嵌套对象**——逐字保留
  `"storage.pack.slot_bytes"`，文件里也就有那个检索词了；
  ② **类型判据再收紧**：`type(v) is T`、`bool` 不冒充 `int`、`int` 值可配 `float`（按浮点算）、
  容器只许一层元素、只收 JSON 能表示的类型；类型与默认值不符**在声明期就炸**；
  ③ **表声明的位子**：`config/tables.yaml`（本体），等存储那轮经 `storage.db.tables` 的文件引用接回。

- 待定 · **"流写" / 定时窗口落盘暂不做**：它等于把"何时落盘"从"进程退出"再添一处，
  而真需要"此刻就是对的"的场合（工具 / 测试）有 `force=True` 与 `sync()` 就够。
  **重启条件**：真出现"长驻进程且外部读者要持续看到较新的文件"这种需求，再论。
  （作者提过这个方向，故记在待定里，不当作已否。）
- 已定 · **后果与注意事项写在代码的 docstring / 注释里，别攒设计稿**（2026-09-29 作者定）：
  这批后果影响都不大，几行说清即可。要落笔的就是上面这组：默认不即时、崩溃丢的是待写那类、
  只读盘不报错、只读得靠 `conf` 自己补、int→float 会按浮点写出去、省略 `type=` 时按默认值判。
  正文（`docs/architecture/config.md`）等引擎落地一并回写，不提前写。
- 已定 · **启动必须容忍值文件缺失 / 陈旧**：值文件是投影，不是启动前提；缺了就按声明重建，
  旧了就按"只补缺失、不改已写"对齐。
- 已定 · **落盘失败（只读盘 / 无权限）不报错**：只记一句日志——它是投影，写不出去不影响本次运行。
- 已定 · **值投影收成单文件**（作者 2026-09-29 定）：不按包树分文件，一个 hub 一份值文件。
  理由：分文件是为"配置量大到离谱"准备的，而配置再大也到不了那个量级；标准定为
  **十万行以内不分**。副产品是省掉三样东西——按包树推坐标的映射、hub 命名空间、
  重名检查（`ConfigConflictError`：没有"别人的文件"这回事了）。
  连带：单文件顶部的 `$schema` 与总词表的对应关系要重新定（分片 `$schema` 已无意义）。
- 已定 · **不改的核心（沿用 2026-09-26 那版的口径）**：声明是唯一事实来源；默认值只写在声明处，
  实现里不抄第二份；**用户改过的值永不覆写**，补只补缺失的键；key 丢且无默认值 → 报错。
- 已定 · **类型由形参给，声明期就校验**（2026-09-29 作者定）：加 `type=`，值写 Python 内置类型即可。

  ```python
  conf("storage.pack.slot_bytes", 65536, type=int, doc="槽长：载体内的定长分配与定位单位")
  conf("web.zoom", 1.0, type=float)
  ```

  理由：比 `Annotated` / 泛型那套省事，声明处一眼看懂；**类型和值不是一回事就被锤**——
  声明的类型与默认值不符、以及写进来的值与该键声明的类型不符（人手改错文件也一样），
  都是**当场报错**，不留到运行期才炸。
- 已定 · **校验口径（判据必须精确，否则误报会变成噪音）**：
  ① 用 `type(value) is T` 判，**不用 `isinstance`**——`isinstance(True, int)` 为真，
  但 `bool` 与 `int` 是两个东西（JSON 也有原生布尔），`type=int` 配 `True` 要拦下；
  ② **唯一允许放宽的是 `int` 值配 `type=float`**（提升，无损）；此时**默认值按浮点写出**
  （`65536` 要落成 `65536.0`），否则读回变整数、自己又被自己拦下；
  ③ 反向（`type=int` 配 `1.5`）**一律报错**，哪怕值是整数值的浮点也不放行。
- 已定 · **类型必须落在 JSON 能表示的那几种里**：`int` / `float` / `bool` / `str` / `list` / `dict`，
  外加 `None`。理由：值文件是 JSON，`bytes` / `datetime` / `Path` / 枚举 / 元组 / 集合
  **落下去就变样或直接写不出去**，所以要在声明期拒绝，而不是等落盘时崩。
  一并一处改进：`None` 成为合法默认值（它本就是合法 JSON 值，"没设"与"设成空"由此可分），
  先前那套 `empty_ok` 不需要了。
- 已定 · **读写两侧同一套校验**：读回来的值也过一遍类型判据——人手改坏文件同样是当场报错，
  不是静默当成另一个类型用。
- 已定 · **省略 `type=` 时的口径**：按默认值自身的类型判（声明天然自洽）；连默认值都没有的键
  只进词表、值丢了报错，词表里记"值必填"、类型不作承诺。
