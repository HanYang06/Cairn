### 一、两层继承：核心 → 延伸概念

- 已定 · **继承核心即认领一个"大概念"**：`Block` 是核心给出的存储载体基类
  （`core/storage/format/block.py`），领域的数据类继承它；继承即登记，表随之诞生。
- 已定 · **"领域"是一种延伸概念，与将来的"插件"同级**：两者都从核心经中间层继承而来。
  故中间层的基座识别的是**延伸概念**这个更宽的概念，登记项带"种类"，
  **不得把"领域"写死**——否则插件只能另起一套。
- 已定 · **中间层不住在 `core` 里**：`core` 只提供**表与机制**，中间层提供**钩子与领域抽象**。
  判据是"内核不得随领域变重"——`core` 只该管事件 / 存储 / 配置 / 异常四件事
  （见 [`内核.md`](内核.md) §一）。落点 `model/shared/`，**不开新顶层包**。
- 已定 · **方向只有 中间层 → core，`core` 永不反向**（`pyproject.toml` 的 import-linter 已拦）。
  内核因此**从不往下够**：它只知道自己的表被灌满了，**不知道自己被挂上了什么**。
- 已定 · **算法层分两级**（作者 2026-10-01 定）：`model/engine/` 放**跨域共用**的重算法，
  判据就是作者那句"这个部分也要用、那个部分也要用"；某个域要特化时**各域自己建目录**
  （如 `model/note/engine/`），互不牵连。`model/engine/` 因此**不 import 任何域的类型**。

### 二、三个角色，职责不重叠

| 角色 | 是什么 | 基类 | 落盘 |
|---|---|---|---|
| `Note` | **领域**：管理 `NoteData`（创建、修改、校验入口） | 延伸概念（中间层） | **不落盘、无自有状态** |
| `NoteData` | 数据载体：**一个 `Block` 子对象**，带自己的校验与锚定机制 | `Block`（core） | 落盘 |
| 命令函数 | 执行：模块级函数 + 装饰器登记，如 `note/save` | 无 | 不落盘 |

- 已定 · **创建一篇笔记 = 落一个 `NoteData`**，不是落一个 `Note`。作者原话的判断：
  "我创建一个笔记的本质行为，创建的不是'笔记'这个东西，而是创建了一个叫做'笔记'的 Block 子对象。"
- 已定 · **`Note` 管 `NoteData`**：对外创建、修改都是 `Note` 的事；`NoteData` 自己不知道
  "这份数据该怎么办"，它只知道"我存了这份数据"，外加它自带的那点机制。
- 已定 · **执行不另立"服务类"**：命令写成分模块级函数、由装饰器登记。
  于是"对象 / 数据 / 执行"三件各有各的家，没有一个类同时揽三样。

### 三、锚定与校验归 `NoteData`

- 已定 · **锚定机制写在 `NoteData` 自己身上**：它用 `attr` 声明稳定锚（如 `note_id`），
  于是"这份数据属于哪篇笔记"是**能从盘上算回来的事实**。
- 已定 · **字段之间的关联校验是 `NoteData` 的责任**（例：几个字段相互关联时的一致性）。
- 现状限制 · **核心不提供跨字段校验钩子**：写入期唯一的判据是"属性值编不进 CBOR 即报错"
  （见 [`属性.md`](属性.md) §一），类型判据只到**单字段**。故关联校验是领域自建的方法，
  内核不为它开口子。
- **重要推论** · **领域不得持有权威状态**（内存态重启即丢）。故"当前是哪一份 `NoteData`"
  必须是**盘上的事实**：`Note` 记住了也不算数。

### 四、登记（触手）

- 已定 · **一切要被认出来的东西都挂在登记表上，不许空悬**。现状与去向：
  **类型登记表**（`core`，已有：`Block` / `Body` 子类即登记）→
  **延伸概念登记表**（中间层，待建：短名、种类、它用到哪些数据类）→
  **命令登记表**（中间层，待建：方法名、参数形状、处理器）。
- 已定 · **命令用装饰器在 import 时登记**，与 `attr`"声明即事实"、`Block`"类型定义即登记"
  同族。装饰器同时供三个消费者：边车分派器、契约生成器、`describe` 发现口。
- 已定 · **不引 pydantic**（会在 `conf` / `attr` 之外立第三套类型词汇）；**不引 OpenAPI**
  （会把 HTTP 心智带回来，与"本地内核不开任何端口"冲突）。
- 未定 · 基类的名字：`Model` 与层名 `py_src/model/` 相撞，倾向 `Domain` 或其他名字。

### 五、未定 / 待裁

- 未定 · **"当前版本"的锚怎么表达**：方向是"写在 `NoteData` 的 `attr` 里 + 倒排查回"，
  即**不新增内核机制**（与 `storage-design.md` §9.1「版本不属于存储」一致）。
  细节（`prev` 链、取 `birth_time` 最大、领域真源表）未定。
- 未定 · **规模纪律**：每抽一个共享件要能说出**第二个调用方**；"插件"是它的第二个调用方，
  但插件本身未实现，故**不预埋插件框架**，只把登记项的"种类"字段留出来
  （判例：`edge` 表形状对、零调用方，照删）。
- 未定 · **命令参数形状在 mypy strict 下怎么保住**（`ParamSpec` / 扩 `tools/mypy_plugin.py`）。
- 未定 · **领域模块的 import 点**：装饰器靠 import 生效，漏 import 即静默丢命令，
  需要一条测试拦"命令表里少了谁"。
