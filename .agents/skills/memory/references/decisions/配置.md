## 配置（**2026-10-04 换成上游引擎 OnConf**）

> 现状：`py_src/core/conf.py` 是**外层**（定配置根 + 转发 `conf` + 定日志去向）；
> **引擎不是本仓的代码**——是 PyPI 包 `onconf`（OnConf，Apache-2.0，`requires-python >=3.14`）。
> 用法契约见 `docs/architecture/py_core/config.md`；本文只记形状与理由。

- 已定 · **内建引擎整条删除，换上游包**（2026-10-04 作者定）：删掉 `py_src/core/conf/`
  （registry / schema / types / params）与 `core.exc` 的 `ConfigError` 一族，
  改依赖 `onconf>=1.0.0`。原来的引擎就是从 Cairn 抽出去的那一个，抽出去之后这边留一份
  等于**同一件事维护两遍**；上游那版多了跨进程专职写者、外科手术式回写、YAML/TOML/.env 后端。

- 已定 · **为此把仓升到 Python 3.14**（2026-10-04 作者定）：OnConf 1.0.0 声明
  `requires-python >=3.14`，且源码里有 PEP 758 写法（`except A, B:` 不带括号），
  **3.13 连解析都过不去**。故 `.python-version` / `requires-python` / ruff `target-version` /
  mypy `python_version` 一并步进；实测 375 项旧测试在 3.14 上原样全绿，故升级本身无代码改动。

- 已定 · **`onconf` 单开一个 PyPI 索引**（2026-10-04）：阿里云镜像**没同步这个包**
  （实测 `simple/onconf/` 返 404，而 `cbor2` / `pytest` 正常）。`pyproject.toml` 里给它加
  `explicit = true` 的 PyPI 索引——那个索引只服务在 `[tool.uv.sources]` 里点名要它的包，
  其余依赖仍走默认镜像，不会把整棵依赖树拉回官方源。

- 已定 · **外层只做三件事**（2026-10-04）：① 定配置根（`CAIRN_CONFIG` → 仓根 `config/`）；
  ② 把 `conf` 转发出去（调用形与旧引擎逐字一致，**声明点一行都不用改**）；
  ③ 定日志去向。**为什么非得有这一层**：OnConf 的引擎是单例且"起来之后不能就地改配置"，
  而配置根由环境旋钮定——故必须在**第一次 `conf()` 之前**把 `home` 定下来，
  而内核的声明模块正是在导入期调 `conf()` 的。

- 已定 · **转发按位置透传，不转抄上游哨兵**（2026-10-04）：OnConf 判"读还是写"靠
  `value` 位拿到的是**不是它自己那个 `MISSING` 哨兵**，而那个哨兵在 `onconf._core`（私有）。
  故外层签名是 `conf(key, *args, ...)`：**给没给第二个参数就是那一条判据本身**，
  不依赖上游任何私有符号。转抄一个自己的哨兵会让 `conf("k")` 变成"把哨兵写进去"。

- 已定 · **日志改去 `<root>/logs/config.log`**（2026-10-04）：OnConf 的日志默认去 `stderr`
  且**每次读都留一行**（不可关闭，是它的审计取舍）。照默认走，一次 `import core` 就往 stderr
  倒十几行，命令行与 pytest 输出全被淹。日志口自己会建父目录，故不需要预建 `logs/`。

- 已定 · **不做键改名**（2026-10-04）：早先那条"八条键按 `<架构层>.<功能域>.<对象>.<属性>`
  改名 + 加 AST 门禁"**从这次替换里摘出去**——那是独立的一件事，混进来会让"换引擎"
  这个改动同时动值文件、文档与全部声明点。现存的键名照旧（`core.log.level` / `pack.max.byte` …）。

### 换引擎带来的语义变化（这是最该记住的一段）

按事实记，不按旧口径；每条都实测或按上游源码核过：

- **未知键（用户自加）会在提交点被清掉**：OnConf 的规则 1「事实有、期望没有 ⇒ 清理」在
  提交点执行，进程退出就是提交点（前提：该进程至少声明过一个键）。
  旧口径"用户自加的键永远留着"**不再成立**——值文件的键空间**由声明定，不由文件定**。
  反过来，**声明过的键、值与格式原样保留**（回写是文本级外科手术，只动该动的那一个值区间）。
- **重复声明不再报错**：同一进程里再声明同一键，OnConf 只更新词表、值文件那边 `op=skip`。
  旧引擎那种"重复声明在启动时炸、报错带上先声明那一处"的看门能力**随引擎一起没了**；
  要它得另找地方做（如一道扫 `conf(...)` 调用点的 AST 门禁）。
- **落盘默认即时**：`flush_window` 默认 `0`，"写只记一笔、退出时统一落盘"不再成立。
- **`conf(k, v)` 返回当前生效值**（文件里已有的优先），不再是"那一处写下的默认值"。
- **读期不做类型转换**：`type=` 只在声明期校验默认值；人手改坏类型**不会当场报错**，
  由取用处（`int(conf(...))` 这类包装函数）收口。错误位置从"声明处"挪到"取用处"。
- **`file=` 值放独立文件的能力没有了**（旧引擎有，但当时已无调用方：表声明那条链整条取消）。
- **异常换成 OnConf 那一族**：`KeyNotRegisteredError` / `KeyHasNoValueError` /
  `TypeConflictError` / `ConfError`；`core.exc` 里那五个 `Config*` 随之删除
  （异常层"不声明没有抛出点的异常"这条规矩也要求删）。

### 上游待办（不是本仓能修的）

- **wheel 缺 `py.typed`**：`pyproject.toml` 声明了 `Typing :: Typed`，实际包里的 wheel
  没有该文件，故 strict 下 import 它必报 `import-untyped`。本仓只能给 `onconf` 那一组开
  `ignore_missing_imports`（已写明"上游补了就删掉这段"）。
- **`EngineParams` 少了 `lock_timeout`**：`Engine.__init__` 有它，`conf(**engine)` 透传它会抛
  `UnknownEngineParamError`。
- 发布出去的 README 仍写"尚未发布到 PyPI / Pre-Alpha 0.1.0"，而版本已是 1.0.0。
