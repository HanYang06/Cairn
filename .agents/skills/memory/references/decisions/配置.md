## 配置（**2026-10-04 换成上游引擎 OnConf；2026-10-07 随 2.0 收口**）

> 现状：`py_src/core/conf.py` 只做**装配**——定配置根（`CAIRN_CONFIG` → 仓根 `config/`）
> ＋关日志的控制台出口；声明与取值一律用上游的 `conf`。
> **引擎不是本仓的代码**——是 PyPI 包 `onconf`（OnConf，Apache-2.0，`requires-python >=3.14`）。
> 用法契约见 `docs/architecture/py_core/config.md`；本文只记形状与理由。

- 已定 · **内建引擎整条删除，换上游包**（2026-10-04 作者定）：删掉 `py_src/core/conf/`
  （registry / schema / types / params）与 `core.exc` 的 `ConfigError` 一族，改依赖 `onconf`。
  原来的引擎就是从 Cairn 抽出去的那一个，抽出去之后这边留一份等于**同一件事维护两遍**。

- 已定 · **为此把仓升到 Python 3.14**（2026-10-04 作者定）：OnConf 声明 `requires-python >=3.14`，
  且源码里有 PEP 758 写法（`except A, B:` 不带括号），**3.13 连解析都过不去**。

- 已定 · **`onconf` 单开一个 PyPI 索引**（2026-10-04）：阿里云镜像**没同步这个包**
  （实测 `simple/onconf/` 返 404）。`pyproject.toml` 里给它加 `explicit = true` 的 PyPI 索引——
  那个索引只服务在 `[tool.uv.sources]` 里点名要它的包。

- 已定 · **外层不再转发 `conf`，只装配**（2026-10-07）：2.0 把引擎参数收进 `AutoConf`、
  参数面封闭成 `key` / `value` / `doc`，转发层赖以存在的"调用形与旧引擎逐字一致"这条理由
  随 `type=` / `force=` 一并消失。故 `core/conf.py` 只剩两件事：定根、关控制台出口；
  声明点与取用点直接 `from onconf import conf`。
  **装配顺序由 `core/__init__.py` 保证**（先 `import core.conf`、再 `import core.params`）：
  导入 `core` 即装配完成，顺序弄反时装配那一句会因"引擎已经启动"当场抛 `ConfError`。
  **`core.conf.sync()` 一并删除**：`flush_window` 缺省 `0`，没有待提交的声明，它退化成空动作，
  全仓唯一调用方（`scripts/docgen.py`）那次调用也已删。

- 已定 · **配置根旋钮仍叫 `CAIRN_CONFIG`**（2026-10-04）：引擎自己的根旋钮是 `ONCONF_HOME`
  （缺省 `./conf`），而本仓的缺省落点是与值文件同处的仓根 `config/`，故仍显式给 `home`。
  它不是配置项，值文件里不会出现。

- 已定 · **控制台日志出口关掉、审计文件留全量**（2026-10-07）：2.0 把 1.0 的单个 `log=` 拆成
  一份记录两个出口——文件无开关（缺省 `<root>/audit.log`）、控制台由 `log_console` 开关。
  内核是被命令行与测试嵌入的一方，一次导入要读十几条键，故关控制台、文件照留。
  1.0 时代"改去 `logs/config.log`、靠日志口自建目录"的做法一并撤掉：那个理由（躲 stderr）
  现在由开关解决，而 2.0 的日志口**明确不建父目录**。

- 已定 · **不做键改名**（2026-10-04）：那件事从换引擎里摘出去，留作独立任务（见 `progress.md`）。

### 2.0 的语义变化（这是最该记住的一段）

按上游源码核过；每条都影响本仓的文档、测试或调用方：

- **未知键运行期不再被清**：删除的判据只在**期望集完整**时成立，而运行期一个进程的期望集
  只是它声明过的那部分，故 `conf()` 的任何出口都不删键；收敛（删多余键、覆盖既存值）
  归命令行 `onconf build` / `sync`。1.0 的口径"键空间由声明定、不由文件定"**反了**。
- **覆盖既存值的能力取消**（1.0 的 `force=True`）：运行期只能补缺失的键，改值改文件。
- **类型整体取消**：`type=` 没了，词表只记键 / 说明 / 默认值；引擎不推断也不转换值。
- **日志拆成两个出口**：控制台可开关，文件无开关。
- **跨进程模型换成"属主进程"**：`.lock` / `.key` 握手文件没了；引擎把创建者的 pid 写进
  `ONCONF_OWNER_PID`，派生进程只读，落盘前比一次 pid。
  **踩点**：父进程导入过 `core` 之后，它 spawn 的 Python 子进程会继承这个变量、
  被判成派生进程（写配置即抛 `ConfError`）。要让子进程当属主，在它的环境里摘掉这一项
  （`tests/core/test_conf.py` 里的子进程就是这么做的）。
- **读会先比文件指纹**（`mtime` ＋ 大小），外部手改下一次读即可见，不再要等一次提交。
- **词表格式变了，但引擎不会因此重写词表**：写盘只由对账动作触发（键缺失，或说明 / 默认值
  与声明不一致）；声明集与登记项都没动时一个字节都不写，旧格式（带 `type`）会一直留在盘上——
  升级那一次要删掉词表再生成一次。`x-onconf-hash` 在 2.0 只被写入，不参与这个判断。

### 上游待办（不是本仓能修的）

- **wheel 缺 `py.typed`**：2.0 的包里仍没有该文件，本仓只能给 `onconf` 那一组开
  `ignore_missing_imports`（已写明"上游补了就删掉这段"）。
- 1.0 时代记的另一个问题（`EngineParams` 少 `lock_timeout`）随 2.0 的参数面消失——
  2.0 的引擎参数里没有这一项，也无经 `conf()` 透传的路径。
