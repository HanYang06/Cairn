## 内核（现行；2026-09-29 重建后重定，2026-10-02 值范式落地）

> 状态：**现行**。本文只记**现在成立的约束与理由**；过程与旧版本不在这里堆（那是 Git 的事）。
> 未定的写"未定"，**不假装已存在**。

### 一、重建的判据（2026-09-29）

- 已定 · **旧实现整条作废、推倒重建**：`src/` 全部旧实现与 `tests/` 全部旧测试删除，
  相对 `main` 共 **137 个文件 / 21045 行**。
  判据：**内核只该管事件 / 存储 / 配置 / 异常四件事，总量应当很小**；旧实现已偏离该目标。
- 已定 · **代码优先、注释写在现场**：设计意图直接写进 docstring；文档与仓库尾巴随后回写。
- 已定 · **随片带最小回归测试**：每落一片内核配对应契约测试，不攒到最后统一补。
- 已定 · **未实现的设计标为「预留 / 草案」**：看到这三个字就**当它不存在**，不得按图索骥。
  这条是防"拿意图当现状"的总闸。

### 二、ID 凭证（2026-09-29）

- 已定 · **算法取 `uuid4()` + `sha256`**，**不用** 26 字符 Crockford ULID，**也不用** BLAKE3。
  理由：不需要时间排序（ID 已带 `birth_time`，排序需求本身不强），且实现更短。
  切换点是 `py_src/core/storage/db/id.py` 的 `new_uuid()` 与 `digest()`。
- 已定 · **内部时间统一 unix 毫秒**（`core/clock.py` 的 `now_ms`）；**ID 的 `birth_time` 用纳秒**。

### 三、事件层（2026-09-29）

- 已定 · **分发自制，不引第三方分发库**。实测 blinker（MIT / 零依赖）有三条与本内核冲突，
  故自写 `core/event/bus.py`（约 70 行、零依赖）：
  ① 投递顺序取 `set` 迭代序（注册 a、b、c，实测调用序 a、c、b），跨次运行都可能不同；
  ② 订阅者抛错会中断后续订阅者；③ `weak=True` 默认静默丢弃闭包与局部函数。
- 已定 · **Bus 契约钉死为四条**：按注册顺序投递、异常隔离并把失败清单交回调用方、
  显式撤订（句柄或上下文管理器）、失败钩子。内核把失败钩子接到日志上。
- **已否掉的路径**：引 blinker + `ordered-set` 换顺序——那是在运行时改第三方库的类属性，
  且依赖从一变成二。blinker 装上后已 `uv remove` 撤净，**不必再评估一遍**。
- 已定 · **事件对象字段借 CloudEvents 口径**：`id` / `source` / `type` / `time` / `subject` / `data`。
  **只借名，不代表实现该规范**（无 `specversion`、无传输绑定）；
  `cloudevents` SDK 不引（自称 work in progress，且多两个依赖）。
- 已定 · **事件只做扇出通知，不建解析器 / 中介者**。判据是**有没有调用方**——
  `core/event/parser.py` 的空桩已删。**重启条件**：出现真正的命令路径，或网络侧上线
  （事件变成数据流）时再设计，届时按类型化处理器 + 中介者重做。

### 四、载体与记录（2026-09-29）

- 已定 · **记录头的 ID 段 = 两套凭证 ＋ 名字 ＋ 签发时刻**（位置段不进记录）：
  名字与签发时刻都要在记录里，否则索引库一丢，"这一格是谁、什么时候签的"就无从复原；
  位置**不能**进记录——扫到它时位置已经由扫描给出。
  `from_record` 对可选字段宽容读回、未知键忽略，故将来加字段不必改旧记录的读法；
  **不伪造签发时间**：记录里没有即取零。
- 已定 · **槽位定位取两数格模型**：载体是一串等大的格子，**记录从格边界开始写，写不下就往后再拼格子**；
  一条记录的位置就是**头一格与末格**两个数字（`SlotRange(first, last)`，闭区间）。
  作者的理由是"**存储怕的是存得莫名其妙**"——两数模型没有解释成本；三数模型带来的
  "槽对齐值 vs 实际占用"两套口径本身就是最难解释的那部分，故一并删除。
  **代价被显式接受并钉进测试**：一条记录至少占一格、格尾补零，
  故格长**取 512 B**（五档相加，最小那一档带默认值）。
- 已定 · **载体文件头 24 字节 = 魔数 8 ＋ 格长 8 ＋ 预留 8**：魔数 `CairnPk1` 末位带布局版本；
  **格长写进文件头、读取一律从文件头读**，故改配置不会让已落盘载体的偏移错位；
  预留段不校验内容，留给将来加字段。**格号自文件头之后起算**，故文件头不必凑成整格。
- 已定 · **hub 是"桶"的新名字**：判据不变（`vault/` 下带 `packs/` 的直接子目录才算 hub），
  代码与注释一律用 hub。**手册 / 文档里不得再出现"桶 / bucket"**（那是旧词）。

### 五、版本不归内核

- 已定 · **版本不归内核**（2026-10-01 随领域架构定）：内核不新增表、列或机制；
  锚写在领域数据类自己的 `Attr` 声明里，由领域自己表达"当前是哪一份"
  （与 `docs/architecture/storage-design.md` §10.1 一致）。
  细节见 [`领域.md`](领域.md) §三、§五。

### 六、类型性质：工具 / 业务两分作废（2026-10-01）

- 已定 · **`Nature` 全砍掉**（作者裁定）：不再区分"工具型"与"业务型"，
  所有实体块**一律可查**；"这类块不进列举"的类别不存在，查询面的代价由界面承担
  （界面按表名分屏，内核只如实列举）。
- 为什么：`Nature.TOOL` 的文档写着"工具型不出现在列举里"，但**全仓没有一处读它**
  （只有测试断言），且它**不进库里任何一列**——即一条**零消费的声明**。
  按本项目自己的判例（"零调用方即脚手架"，`edge` 表照此删除），它应当删掉，
  而不是接线。重启条件：将来真出现"内核机制型块"时再加回来。

### 七、块形状的声明与身份（2026-10-02 值范式落地）

- 已定 · **声明写在类体上，形态是描述符**：`title: str = Attr("")`（进块记录并进反表）、
  `lines: list[str] = Body([])`（进内容记录）、裸赋值（照样落盘，没有索引加持）。
  注解是字段类型（给 mypy 看），右值是落点声明；**运行期不认注解**，故不需要 mypy 插件。
  细则见 [`属性.md`](属性.md) §二与 `docs/architecture/storage-design.md` §3。
- 已定 · **落点只有三档，没有"声明了却不索引"那一档**：`Attr` 用了就进反表，
  **没有 `indexed=` 一类开关**；不要索引就别声明。
- 已定 · **身份由调用方给，两条写法收敛在基座一处**：`self.id = ID(self)` 自己签、
  `super().__init__(self.id)` 递给基座，或把签好的递进来。
  **零参构造也是一个块**——基座自己现签一个，索引块按需造出来走的正是这条路。
- 已定 · **有 ID 才有表**：用了 ID 的类型库里就有一张身份表；
  **只活在载荷里的结构没有 ID**，故不建表（领域载荷里那些 dataclass 结构就是这一档）。
- 已定 · **`@dataclass` 从块这一层退场**：块要的是"类体声明 ＋ 描述符"，
  而 `@dataclass` 只认注解、拿不到落点。值对象（纯数据、不建表）仍可用它。
- 已定 · **没有类型登记表**：类的子类清单在运行期就能算出，不必另存一份；
  也没有 `adopt()` / `install_core_types()` 这类显式收养动作。

### 八、装配与命令面（2026-10-02）

- 已定 · **`Kernel` 只做接线**（`core/init.py`）：路径约定（`catalog.db` / `<hub>/packs/`）、
  `bind(engine)` 把能力接上、总线的失败钩子接日志。
  **一个进程一根线**，`close()` 解开；索引库**惰性开**，故"只想读载体"的场合不会凭空多一个库文件。
- 已定 · **`Kernel` 上没有 `store` / `load` / `drop` / `locate` / `patrol` / `repair` /
  `reindex` / `survey` / `compact`**：写由块自己发起（`block.save()`）、读由块自己发起
  （`NoteData.fetch(identity)`）、整库的诊断走命令面、回收走模块级 `sweep(engine)`。
  判据：内核只该管事件 / 存储 / 配置 / 异常四件事，方法面每多一个都要说得出调用方。
- 已定 · **命令面是读与诊断**（`core/api.py`）：七个方法 `tables` / `hubs` / `rows` / `locate` /
  `record` / `stats` / `delete`，结果只落在 JSON 域里（身份、位置、计数、记录原文的 base64），
  **不解领域载荷**——解载荷是领域格式层的活。
  **命令面里没有 `store`**：写由领域块自己发起，放一个 `store` 就把"谁决定落点"这条断了；
  删除是例外（整库动作）。
- 待裁 · **命令面契约**：子命令集与退出码口径、库根旋钮，均待作者裁定；
  `py_src/app/sidecar.py` 的帧协议已接上这一面（一个进程一根线、请求与回答配对、
  内核到壳的通知帧已接线）。
- 已定 · **事件只有两条**（`core/event/catalog.py`）：`object.put` 与 `object.deleted`，
  都由存储的写路径发出；`budget.exhausted` 已删（配额 / 档位那套机制不存在）。
  加事件的门槛是先问"是不是一次通知"、再问"有没有人订"。

### 九、魔法与类变量：少用（2026-10-02 门禁落地）

- 已定 · **"少用魔法"由门禁定量把关**：`scripts/magic.py --check` 扫**类上的 dunder**，
  两道判据——**豁免表逐个比对**（现在不用的写法不得留在表里）与
  **用到魔法的类占比上限 0.30**（现状 0.21）。`__init__` 不计，同名重载只算一次。
  已接进 pre-commit 与 CI；规矩写在 `rules/references/quality.md`。
- 为什么要有上限：魔法是"读的人必须知道解释器怎么调它"才能看懂的语法，
  在声明范式已经确定之后，它的每一处新增都应当是一次显式取舍，而不是无意识的写法。
- 已定 · **类变量也少用**：类的属性优先表达"这个类型是什么"（如索引块的 `manages`），
  而不是当可变状态的寄存处——可变状态放实例，声明放类体上的描述符。
