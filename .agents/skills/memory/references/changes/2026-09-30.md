- 2026-09-30 · 已定 · **片 11：表自诞生——类型反查 → 声明文件 → 库；`record` 单表拆成 `block` / `body`**：
  作者口径是"**表不该手工拆**"：代码写好了，运行一遍它自然把表拆出来；手工拆的和它自动拆的有明显区别。
  据此落成一条链，落在四处：
  **① 反查（`storage/registry.py` + `format/block.py`）**：`Body` / `Block` 在**类定义时机**
  由 `__init_subclass__` 登记自己（名字、表名、它持有的 ID 字段与指向的引用）；
  `TypeDecl` 把关（字段必须在落盘子集、必须有 `value_uuid`、引用必须说清目标）；
  `Registry` 查重（同名不同形状、同表不同名字都报错；`@dataclass(slots=True)` 重建类造成的
  **同形状重放**视为幂等）。**没走"扫描全书"那条路**：慢，且会把没被导入的类型悄悄漏掉。
  **子类不继承父类的表名**（`__table__` 只认本类自己写下的），否则子类会顶掉父类那张表。
  **② 推形状（`storage/tablegen.py`）**：登记 → `TableSpec`（身份列 ＋ 指针两列 ＋ `kind` ＋
  观测列 ＋ 两个时刻）；`body` 表没有 `kind`；位置观测列两张表都有（每条载体记录都要有一行）。
  **③ 写文件（`tablegen.sync`）**：文件不在整份生成，在则**只追加不覆写**——
  登记表里有、文件里没有的表与列补进去，已有的表与列一个字不改，人手加的列也不删；
  要淘汰的旧表由 `Kernel.SUPERSEDED_TABLES = ("record",)` **显式点名**，且**先按原始项摘掉
  再逐张过严格解析口**（旧形状按新判据本来就不合规，先解析就永远淘汰不掉）。
  **④ 建库（`init.kernel_declaration`）**：每次装配先跑一次投影（幂等），再拿现算的声明开库。
  **连带**：`record` 单表与 `id(scope).name` 那套判别列退役（`IDENTITY_TABLE` /
  `SCOPE_QUALIFIER` 与身份表特例校验全删）；`id(名字).字段` 的语义收紧为
  **不写名字＝本行主语（IDENTITY）、写了名字＝指向别处（REFERENCE）**；
  行层拆成 `BlockRow` / `BodyRow`（`put_block` / `put_body` / `blocks_by_body` / `bodies_by_hash` …），
  `move_*` 只改坐标；**块载荷的指针改成两套凭证**（保留键 `\x00cairn.body_ref`，
  `body_ref_of()` 对只带一半的映射一律当内容读）；重建按**载荷**判进哪张表（类型为空也认得出）；
  巡检两张表各比一遍、补行带哪种行就补哪种；`storage.db.tables` 配置键删除（文件名是常量）。

  免得同一张表里两个 ID 的同名字段撞名；身份表的判别列 `id(scope).name` 例外，落的仍是 `name`。
